## 核心原则

### 1. 真实性优先
- **严格基于简历内容**：所有问题必须关联到简历中明确提到的经历
- **不虚构案例**：禁止编造简历中没有的项目或经历
- **不夸大成果**：保持简历中的数据和描述的准确性

### 2. 可验证性
- **每个问题都有依据**：在问题中标注来源于简历的哪个部分
- **提供上下文**：问题必须包含简历中的具体信息作为背景
- **避免抽象提问**：所有问题都应该针对具体的工作经历或项目

### 3. 逻辑一致性
- **时间线合理**：问题的顺序应遵循简历中的时间顺序
- **角色清晰**：问题中的角色描述必须与简历一致
- **公司/项目信息准确**：使用简历中的准确名称和信息

## 简历信息提取策略

### 提取简历中的关键信息

#### 1. 工作经历提取
提取每个工作经历中的以下信息：
- 公司名称（准确名称）
- 职位名称（准确名称）
- 工作时间段
- 主要职责（逐条提取）
- 关键成果（包含具体数据）

**示例**：
```
简历原文：
"2019.06-2022.03 腾讯科技有限公司 高级Java工程师
负责核心支付系统的开发和优化，将系统吞吐量提升50%
"

提取信息：
- 公司：腾讯科技有限公司
- 职位：高级Java工程师
- 时间：2019.06-2022.03
- 职责：核心支付系统开发和优化
- 成果：吞吐量提升50%
```

#### 2. 项目经验提取
提取每个项目中的以下信息：
- 项目名称（准确名称）
- 项目周期
- 项目角色
- 技术栈（准确列出的技术）
- 项目规模（团队人数、用户量等）
- 项目成果（具体数据）

**示例**：
```
简历原文：
"微信支付小程序项目 | 2020.01-2020.12
技术负责人，带领8人团队
技术栈：Spring Boot、MySQL、Redis
实现日均交易量1000万+，峰值QPS达到50000"

提取信息：
- 项目：微信支付小程序项目
- 周期：2020.01-2020.12
- 角色：技术负责人
- 团队：8人
- 技术栈：Spring Boot、MySQL、Redis
- 规模：日均1000万+，峰值QPS 50000
```

#### 3. 技能清单提取
提取简历中明确列出的技能：
- 编程语言（具体版本）
- 框架/库（具体名称和版本）
- 工具（具体名称）
- 认证/证书（准确名称）

**示例**：
```
简历原文：
"技能：Java、Python、Spring Boot 2.5、MyBatis、MySQL、Redis、Docker"
"证书：AWS认证解决方案架构师"

提取技能：
- Java
- Python
- Spring Boot 2.5
- MyBatis
- MySQL
- Redis
- Docker
- AWS认证解决方案架构师
```

#### 4. 教育背景提取
- 学校名称
- 专业名称
- 学历
- 毕业时间
- 相关课程（如提到）
- 成绩/排名（如提到）

## 面试问题生成规则

### 规则1：每个问题必须引用简历原文
**错误示例**：
```
Q: 你在处理高并发问题时有什么经验？
```
**问题**：没有引用简历中的具体信息

**正确示例**：
```
Q: 在腾讯科技工作期间，你负责的核心支付系统将吞吐量提升了50%，
请具体描述你是如何实现这个性能优化的？使用了哪些技术手段？
```
**优点**：
- 引用了公司名称（腾讯科技）
- 引用了具体项目（核心支付系统）
- 引用了具体成果（吞吐量提升50%）
- 问题基于真实经历

### 规则2：问题必须包含简历中的上下文
**错误示例**：
```
Q: 请介绍一下你的团队管理经验。
```
**问题**：过于抽象，没有上下文

**正确示例**：
```
Q: 在微信支付小程序项目中，你作为技术负责人带领8人团队完成了
日均1000万+交易量的目标，请描述你在团队协作、任务分配和
技术决策方面的具体做法。
```
**优点**：
- 包含项目名称
- 包含团队规模（8人）
- 包含项目成果（日均1000万+）
- 针对具体管理职责提问

### 规则3：禁止询问简历中没有的经历
**错误示例**（假设简历中没有提到Kubernetes）：
```
Q: 你在项目中是如何使用Kubernetes进行容器编排的？
```
**问题**：简历中没有提到Kubernetes，属于AI幻觉

**正确示例**：
```
Q: 简历中提到你在项目中使用Docker，请详细说明Docker在
微信支付小程序项目中的应用场景和部署方式。
```
**优点**：
- 基于简历中确实提到的Docker
- 不虚构简历中没有的技术

### 规则4：问题要聚焦简历中的具体细节
**错误示例**：
```
Q: 你在腾讯科技学到了什么？
```
**问题**：过于宽泛

**正确示例**：
```
Q: 在腾讯科技负责核心支付系统的2年多时间里，你提到将系统
吞吐量提升了50%，请分享在这个优化过程中遇到的最大技术挑战，
以及你是如何解决这个问题的？
```
**优点**：
- 聚焦具体成果（吞吐量提升50%）
- 引用具体时间（2年多）
- 针对具体技术挑战提问

### 规则5：技能类问题要关联实际应用
**错误示例**：
```
Q: 请讲讲你对Spring Boot的理解。
```
**问题**：过于理论化

**正确示例**：
```
Q: 简历中提到你熟练使用Spring Boot 2.5，在核心支付系统开发中，
你是如何利用Spring Boot的特性解决实际问题的？请举例说明。
```
**优点**：
- 关联简历中的具体版本（Spring Boot 2.5）
- 关联具体项目（核心支付系统）
- 要求结合实际应用

## 避免AI幻觉的方法

### 方法1：问题生成前必须先验证简历内容
**流程**：
1. 提取问题相关的简历内容
2. 验证该内容是否真实存在于简历中
3. 只有验证通过才能生成问题

**示例**：
```
验证检查清单：
□ 公司名称是否与简历一致？
□ 项目名称是否与简历一致？
□ 时间段是否与简历一致？
□ 技术栈是否在简历技能清单中？
□ 成果数据是否与简历一致？
```

### 方法2：使用模板化生成，避免自由创作
**问题模板**：
```
模板1（工作经历深挖）：
"在【公司名称】担任【职位名称】期间，简历中提到【具体职责/成果】，
请详细描述你的具体工作内容和实现过程。"

模板2（项目经验深挖）：
"关于【项目名称】项目，简历中提到你使用【技术栈】完成了【具体成果】，
请分享你在项目中的角色和主要贡献。"

模板3（技能应用深挖）：
"简历中提到你掌握【技能名称】，在【项目/公司】中你是如何应用
这个技能的？遇到了什么挑战？如何解决的？"
```

### 方法3：在问题中添加简历来源标注
**格式**：
```
Q: [来源：简历-工作经历2] 在【公司名称】...
Q: [来源：简历-项目经验1] 关于【项目名称】...
Q: [来源：简历-技能清单] 关于【技能名称】...
```

**作用**：
- 明确问题依据
- 方便验证真实性
- 避免无中生有

### 方法4：禁止使用"假设性"问题
**错误示例**：
```
Q: 假设你负责一个大型项目，你会怎么做？
Q: 如果遇到XX问题，你会怎么处理？
```
**问题**：假设性问题容易导致AI幻觉

**正确示例**：
```
Q: 在微信支付小程序项目中，你遇到了什么技术难题？
你是如何解决的？（基于简历中提到的真实项目）
```

### 方法5：生成后进行真实性检查
**检查清单**：
```
□ 问题的公司名称是否在简历中？
□ 问题的项目名称是否在简历中？
□ 问题的技术栈是否在简历技能清单中？
□ 问题提到的时间段是否与简历一致？
□ 问题提到的人数/规模是否与简历一致？
□ 问题提到的成果数据是否与简历一致？
```

如果任何一项答案为"否"，则该问题无效，需要重新生成。

## 问题质量检验标准

### 必须满足的标准

#### 1. 可追溯性
- **标准**：每个问题都能在简历中找到明确出处
- **检验方法**：标注问题引用的简历部分
- **示例**：
  ```
  [通过] 通过：Q: [简历-工作经历2] 在腾讯科技...
  [不通过] 不通过：Q: 请介绍一下你的云计算经验...
  ```

#### 2. 准确性
- **标准**：问题中的所有信息必须与简历完全一致
- **检验方法**：对比简历原文
- **示例**：
  ```
  [通过] 通过：简历说"Spring Boot 2.5"，问题说"Spring Boot 2.5"
  [不通过] 不通过：简历说"Spring Boot 2.5"，问题说"Spring Boot 3.0"
  ```

#### 3. 具体性
- **标准**：问题必须包含具体的项目、公司、技术或数据
- **检验方法**：检查是否有具体名词和数字
- **示例**：
  ```
  [通过] 通过：Q: 在微信支付小程序项目中，作为技术负责人带领8人团队...
  [不通过] 不通过：Q: 请介绍你的项目管理经验...
  ```

#### 4. 相关性
- **标准**：问题必须与岗位要求相关
- **检验方法**：对比岗位JD（Job Description）
- **示例**：
  ```
  [通过] 通过：岗位要求"Java开发"，问题关于Spring Boot应用
  [不通过] 不通过：岗位要求"Java开发"，问题关于Python数据分析
  ```

### 禁止出现的问题类型

#### 1. 虚构经历类
```
[禁止] "你在阿里云工作期间..."
（简历中没提到阿里云）
```

#### 2. 虚构技术类
```
[禁止] "你是如何使用Kubernetes的？"
（简历中没提到Kubernetes）
```

#### 3. 虚构成果类
```
[禁止] "你是如何实现用户增长200%的？"
（简历中没提到这个成果）
```

#### 4. 泛化抽象类
```
[禁止] "请谈谈你的工作经历"
（没有具体项目或公司）
```

#### 5. 假设性类
```
[禁止] "如果遇到XX问题，你会怎么处理？"
（基于假设而非真实经历）
```

## 面试问题生成完整流程

### 步骤1：简历信息提取
1. 读取简历全文
2. 提取所有工作经历（公司、职位、时间、职责、成果）
3. 提取所有项目经验（项目、角色、技术栈、成果）
4. 提取所有技能清单
5. 提取教育背景

### 步骤2：岗位需求分析
1. 解析岗位JD
2. 提取岗位要求的核心技能
3. 提取岗位要求的经验类型

### 步骤3：匹配简历与岗位
1. 找出简历中与岗位要求匹配的经历
2. 找出简历中与岗位要求匹配的项目
3. 找出简历中与岗位要求匹配的技能

### 步骤4：生成面试问题
1. **自我介绍**：基于简历中最匹配的经历
2. **简历深挖**：针对每个匹配的工作经历/项目生成2-3个问题
3. **技能应用**：针对每个匹配的技能生成应用类问题
4. **行为面试**：基于简历中的具体案例生成STAR问题

### 步骤5：问题真实性验证
对每个问题执行：
```
验证流程：
1. 标注问题引用的简历部分
2. 对比简历原文，确认信息准确
3. 确认没有虚构任何内容
4. 确认问题足够具体
5. 确认问题与岗位相关
```

### 步骤6：问题质量检查
```
质量检查清单：
□ 每个问题都能追溯到简历原文
□ 问题中的公司/项目名称与简历一致
□ 问题中的技术栈与简历一致
□ 问题中的时间/规模数据与简历一致
□ 问题包含具体的上下文信息
□ 问题与岗位要求相关
□ 没有使用假设性表述
□ 没有虚构简历中没有的经历/技术/成果
```

## 示例演示

### 案例：高级Java工程师岗位

#### 简历内容（提取）：
```
工作经历：

开发经验，以及你作为技术负责人带领团队完成微信支付小程序项目的经历。"
```
[通过] 基于简历中的两个核心经历

**Q2 工作经历深挖**
```
"[来源：简历-工作经历1] 在腾讯科技担任高级Java工程师的近3年时间里，
你提到将核心支付系统的吞吐量提升了50%。请详细描述：
1. 优化前系统的主要瓶颈是什么？
2. 你采取了哪些具体优化措施？
3. 每项措施带来了多大的性能提升？
4. 优化过程中遇到的最大技术挑战是什么？"
```
[通过] 引用具体公司、职位、时间、成果
[通过] 问题具体且可验证

**Q3 项目经验深挖**
```
"[来源：简历-项目经验1] 关于微信支付小程序项目，你作为技术负责人
带领8人团队，使用Spring Boot 2.5、MySQL、Redis等技术栈，
实现了日均1000万+的交易量。请分享：
1. 你是如何进行技术选型的？为什么选择这些技术？
2. 团队如何分工协作的？
3. 项目中最棘手的技术问题是什么？如何解决的？
4. 如何保证系统的稳定性和安全性？"
```
[通过] 引用具体项目、角色、团队规模、技术栈、成果
[通过] 问题全面且基于真实经历

**Q4 技能应用深挖**
```
"[来源：简历-技能清单] 简历中提到你熟练使用Spring Boot 2.5，
在核心支付系统和微信支付小程序项目中，Spring Boot发挥了
哪些关键作用？请具体说明在某个场景下，你是如何利用
Spring Boot的特性解决问题的？"
```
[通过] 关联具体项目和技能版本
[通过] 要求结合实际应用场景

**Q5 STAR行为面试**
```
"[来源：简历-项目经验1] 在微信支付小程序项目中，你带领8人团队
面临日均1000万+交易量的挑战。请用STAR法则描述一次你在
项目中解决团队冲突或协调资源困难的经历：
- 情境：当时的情况是什么？
- 任务：你需要解决什么问题？
- 行动：你具体做了什么？
- 结果：最终取得了什么成效？"
```
[通过] 基于真实项目背景
[通过] 使用简历中的具体数据

## 常见错误及纠正

### 错误1：虚构技术
```
[禁止] 错误问题："你是如何使用Kubernetes进行容器编排的？"
问题：简历中没有提到Kubernetes

[正确] 正确问题："简历中提到你使用Docker，请详细说明在微信支付
小程序项目中，Docker是如何应用的？具体的容器化部署流程是什么？"
纠正：基于简历中真实提到的Docker
```

### 错误2：虚构公司
```
[禁止] 错误问题："在阿里云工作期间，你学到了什么？"
问题：简历中没有提到阿里云

[正确] 正确问题："在腾讯科技工作期间，你将核心支付系统的吞吐量
提升了50%，请分享这个优化过程中的关键经验。"
纠正：基于简历中真实的公司经历
```

### 错误3：虚构成果
```
[禁止] 错误问题："你是如何实现用户增长200%的？"
问题：简历中没有提到用户增长数据

[正确] 正确问题："你提到将系统吞吐量提升了50%，请详细说明实现
这个成果的具体方法和过程。"
纠正：基于简历中真实的成果数据
```

### 错误4：过于抽象
```
[禁止] 错误问题："请介绍一下你的项目管理经验。"
问题：没有具体上下文

[正确] 正确问题："在微信支付小程序项目中，你作为技术负责人带领8人
团队，是如何进行任务分配、进度管理和团队协调的？"
纠正：添加具体项目和团队背景
```

## 总结

生成面试问题的核心原则：
1. **严格基于简历**：所有问题必须引用简历中的真实内容
2. **具体化**：每个问题都包含具体的公司、项目、技术或数据
