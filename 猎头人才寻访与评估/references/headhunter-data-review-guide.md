# 猎头数据复盘：用三张表让效率瓶颈自己现身

## 目录

## 概览

本指南帮助猎头顾问通过数据复盘识别效率瓶颈，将主观感受转化为可量化、可追踪的改进方向。核心工具是三张核心数据表（日报表、周报表、月报表），配合MECE分析法拆解Offer被拒的真正原因。

## 一、三张核心数据表

### 1.1 日报表——"今天卡在哪"

日报表追踪三个最核心的 daily metrics：

#### 指标一：电话接通率

| 字段 | 说明 |
|------|------|
| 统计公式 | 成功接通数量 / 每日拨打数量 |
| 异常信号 | 某天接通率骤降 |
| 排查方向 | 开场白是否生硬急促？拨打时段是否合适（午休、深夜是重灾区）？ |

#### 指标二：添加微信率

| 字段 | 说明 |
|------|------|
| 统计公式 | 愿意加微信人数 / 成功接通人数 |
| 异常信号 | 比率低 |
| 根因分析 | 沟通中没有建立信任感或价值感——首次交流没有给出让对方感兴趣的点 |

#### 指标三：A级转化率

| 字段 | 说明 |
|------|------|
| 定义 | 有明确意向、一周内能推进到推荐的候选人，占接通人数的比例 |
| 异常信号 | 转化率低 |
| 根因分析 | 需求挖掘不精准，或者对人选和职位的匹配度判断失误 |

#### 作用

每天花10分钟填表，能迅速发现当天哪个环节"卡壳"，及时微调话术或目标人选画像。

---

### 1.2 周报表——"本周哪个职位在漏血"

周报表关注两个中周期指标：

#### 指标一：职位关闭周期

| 字段 | 说明 |
|------|------|
| 定义 | 从接到职位需求到候选人入职，平均需要多少天 |
| 异常信号 | 周期过长 |
| 根因分析 | 寻源效率低、面试安排拖沓、或者客户反馈慢 |

#### 指标二：Offer拒绝率

| 字段 | 说明 |
|------|------|
| 定义 | 推荐成功的候选人中，有多少在拿到Offer后拒绝 |
| 分析方法 | 结合候选人反馈细分原因（见MECE分析部分） |

#### 作用

一周一次回顾，能发现流程的系统性瓶颈在哪里，集中攻克而不是四处救火。

---

### 1.3 月报表——"哪些客户在偷走你的时间"

月报表记录一个核心指标：

#### 指标：客户反馈延迟天数

| 字段 | 说明 |
|------|------|
| 定义 | 从提交候选人到收到客户反馈的平均间隔天数 |
| 延迟原因标注 | HR太忙、决策链长、需求不明确 |
| 分析价值 | 按月统计可以看出哪些客户存在习惯性延迟，提前设预期、做提醒 |

#### 作用

避免让"等反馈"变成黑洞——把不可控的等待，转化为可管理的信息流。

---

## 二、用MECE分析法拆解"Offer被拒"的真正原因

当Offer被候选人说"不"的时候，猎头的本能反应是"他不想走"。但数据复盘要求你刨根问底——真正的原因可能藏在水面之下。

### MECE分析法（相互独立、完全穷尽）

把Offer被拒的原因拆成不重叠、不遗漏的维度，逐一排查。

---

### 六大拒绝维度

#### 维度一：薪酬相关

| 子维度 | 具体表现 |
|--------|----------|
| 基础薪资 | 低于候选人预期 |
| 奖金结构 | 不清晰或风险过高 |
| 股权激励 | 价值感知不足 |

#### 维度二：团队与文化

| 子维度 | 具体表现 |
|--------|----------|
| 管理风格 | 对直属上级管理风格有顾虑 |
| 团队氛围 | 协作模式不匹配 |
| 企业文化 | 与个人价值观冲突 |

#### 维度三：工作内容

| 子维度 | 具体表现 |
|--------|----------|
| 岗位职责 | 与预期不符 |
| 晋升路径 | 不明确 |
| 工作强度 | 出差频率过高 |

#### 维度四：通勤与生活

| 子维度 | 具体表现 |
|--------|----------|
| 通勤距离 | 上班距离过远、交通不便 |
| 迁移成本 | 搬迁成本高、家庭安置困难 |

#### 维度五：风险与稳定性

| 子维度 | 具体表现 |
|--------|----------|
| 公司前景 | 对公司前景存疑 |
| 裁员风险 | 行业或职位存在裁员风险 |

#### 维度六：外部因素

| 子维度 | 具体表现 |
|--------|----------|
| 原公司挽留 | 临时加薪/升职挽留 |
| 家庭因素 | 伴侣意见影响 |

---

### MECE分析操作方法

在周报表的"Offer拒绝率"旁，增设"拒绝原因归类"字段，用六个维度标记。每周统计各维度占比：

| 归类结果 | 改进方向 |
|----------|----------|
| 薪酬相关占比40% | 谈薪策略出了问题——没有提前摸清候选人底线 |
| 团队与文化占比高 | 面试辅导忽略了对团队氛围的探讨 |

这样，笼统的"Offer被拒"就变成了一个可以追踪、可以改进的具体环节。

## 三、把数据复盘变成每日习惯

### 固定时间

| 报表 | 填写时间 |
|------|----------|
| 日报 | 下班前5分钟 |
| 周报 | 周五下午 |
| 月报 | 月初第一天 |

### 限定指标

只盯最重要的3-5个指标，不要搞大而全的表格。**指标太多等于没有指标**。

### 问题闭环

```
发现异常 -> 分析原因 -> 制定改动 -> 下次复盘验证
     ^                                            v
     <-<-<-<-<-<-<-<- 形成不断改进的正向循环 <-<-<-<-<-<-<-<-<-<-<-
```

### 团队共享

把表格变成团队可见的仪表盘，让每个人知道"卡点"在哪里，形成共同改进的压力和动力。

## 四、不同薪资候选人，数据表重点各不同

数据表不是千篇一律的。高薪候选人和普通候选人，数据追踪的重点有差异。

### 年薪50万以下候选人

| 重点指标 | 原因 |
|----------|------|
| 接通率 | 这个段位的候选人选择多，任何沟通疏漏会直接导致失联 |
| 添加微信率 | 犹豫成本低，需要快速建立信任 |

### 年薪50-100万候选人

| 重点指标 | 原因 |
|----------|------|
| Offer拒绝率 | 决策更理性 |
| 拒绝原因归类 | 家庭因素、伴侣意见等隐性原因占比更高 |

**关键动作**：推荐前就把家庭变量问清楚。

### 年薪100万以上候选人（MPC）

| 重点指标 | 原因 |
|----------|------|
| 跟进节奏 | MPC的失联复活成本 = 新拓成本的5倍 |
| 沟通质量 | 这类候选人一般不会主动说"我还在考虑"，但沉默不等于满意 |

**关键动作**：宁可多花时间在前期确认意向，也不可后期救火。

### Python脚本：生成matplotlib图表并base64内嵌

**说明**：以下脚本用于生成符合红线v5.7的图表，图片base64内嵌，不依赖外部链接。

```python
"""
猎头数据复盘看板 - matplotlib图表生成脚本
红线合规版：不依赖CDN，所有图片base64内嵌
"""

import matplotlib
matplotlib.use('Agg')  # 非交互式后端
import matplotlib.pyplot as plt
import matplotlib.patches as mpatches
import base64
from io import BytesIO

def generate_bar_chart(data_dict, title, filename=None):
    """
    生成柱状图，图片以base64形式返回
    
    参数：
        data_dict: dict，键为标签，值为数值
        title: str，图表标题
        filename: str，可选，保存文件名
    返回：
        str: base64编码的图片字符串
    """
    # 设置中文字体
    plt.rcParams['font.sans-serif'] = ['WenQuanYi Micro Hei', 'SimHei', 'Arial Unicode MS']
    plt.rcParams['axes.unicode_minus'] = False
    
    fig, ax = plt.subplots(figsize=(8, 4))
    
    labels = list(data_dict.keys())
    values = list(data_dict.values())
    
    # 创建颜色列表
    colors = ['#1890ff' if v >= 70 else '#faad14' if v >= 50 else '#ff4d4f' for v in values]
    
    bars = ax.barh(labels, values, color=colors, height=0.6)
    
    # 添加数值标签
    for bar, val in zip(bars, values):
        ax.text(val + 2, bar.get_y() + bar.get_height()/2, f'{val}%', 
                va='center', fontsize=10)
    
    ax.set_xlim(0, 110)
    ax.set_title(title, fontsize=14, fontweight='bold', pad=10)
    ax.set_xlabel('百分比 (%)')
    
    # 移除边框
    ax.spines['top'].set_visible(False)
    ax.spines['right'].set_visible(False)
    
    plt.tight_layout()
    
    # 保存为BytesIO对象
    buffer = BytesIO()
    plt.savefig(buffer, format='png', dpi=150, bbox_inches='tight', 
                facecolor='white', edgecolor='none')
    buffer.seek(0)
    
    # 转换为base64
    img_base64 = base64.b64encode(buffer.read()).decode('utf-8')
    
    plt.close()
    
    if filename:
        with open(filename, 'wb') as f:
            f.write(base64.b64decode(img_base64))
    
    return img_base64

def generate_pie_chart(data_dict, title):
    """
    生成饼图，图片以base64形式返回
    """
    plt.rcParams['font.sans-serif'] = ['WenQuanYi Micro Hei', 'SimHei']
    plt.rcParams['axes.unicode_minus'] = False
    
    fig, ax = plt.subplots(figsize=(6, 6))
    
    labels = list(data_dict.keys())
    sizes = list(data_dict.values())
    
    # 颜色方案
    colors = ['#1890ff', '#52c41a', '#faad14', '#ff4d4f', '#722ed1', '#13c2c2']
    
    wedges, texts, autotexts = ax.pie(sizes, labels=labels, autopct='%1.1f%%',
                                      colors=colors[:len(sizes)], startangle=90)
    
    for text in texts:
        text.set_fontsize(10)
    for autotext in autotexts:
        autotext.set_color('white')
        autotext.set_fontsize(9)
    
    ax.set_title(title, fontsize=12, fontweight='bold', pad=10)
    
    plt.tight_layout()
    
    buffer = BytesIO()
    plt.savefig(buffer, format='png', dpi=150, bbox_inches='tight',
                facecolor='white', edgecolor='none')
    buffer.seek(0)
    
    img_base64 = base64.b64encode(buffer.read()).decode('utf-8')
    
    plt.close()
    
    return img_base64

# 使用示例
if __name__ == "__main__":
    # 示例数据
    offer_reasons = {
        '薪酬相关': 40,
        '团队与文化': 25,
        '外部因素': 15,
        '通勤与生活': 10,
        '其他': 10
    }
    
    # 生成柱状图
    bar_img = generate_bar_chart(offer_reasons, 'Offer拒绝原因分布')
    
    # 生成饼图
    pie_img = generate_pie_chart(offer_reasons, 'Offer拒绝原因占比')
    
    # 在HTML中使用：
    # <img src="data:image/png;base64,{bar_img}" />
    # <img src="data:image/png;base64,{pie_img}" />
    
    print("图表生成完成，base64字符串可用于HTML嵌入")
```

## 七、脱敏处理规范

在上传任何附件信息至AI系统时，务必做好脱敏措施，避免企业/个人敏感信息或商业机密外泄。确保在保护企业/个人数据安全的同时，充分利用AI技术提升运作效率和准确性。

### 必须脱敏的字段

| 字段类型 | 脱敏示例 |
|----------|----------|
| 候选人姓名 | [候选人A]或[姓名] |
| 客户公司名称 | [公司名称] |
| 项目名称 | [项目名称] |
| 具体薪资数字 | [薪资信息] |
| 候选人手机 | [手机号] |
| 候选人邮箱 | [邮箱] |

## 招聘漏斗分析

### 漏斗模型定义

招聘漏斗是将招聘流程各个阶段的候选人数量可视化，追踪每个环节的转化率。

### 标准招聘漏斗阶段

| 阶段 | 指标名称 | 说明 |
|------|----------|------|
| L1 | 简历获取 | 收到的简历总数 |
| L2 | 简历筛选 | 通过初筛的简历数 |
| L3 | 电话沟通 | 完成电话沟通的人数 |
| L4 | 面试邀请 | 发送面试邀请的人数 |
| L5 | 初试 | 完成初试的人数 |
| L6 | 复试 | 完成复试的人数 |
| L7 | Offer | 发放Offer的人数 |
| L8 | 入职 | 实际入职的人数 |

### 漏斗转化率计算

| 指标 | 计算公式 | 健康范围 |
|------|----------|----------|
| 初筛通过率 | L2/L1 | 30%-50% |
| 电话沟通率 | L3/L2 | 60%-80% |
| 面试邀请率 | L4/L3 | 40%-60% |
| 初试完成率 | L5/L4 | 70%-90% |
| 复试完成率 | L6/L5 | 80%-95% |
| Offer接受率 | L7/L6 | 60%-80% |
| 入职率 | L8/L7 | 80%-95% |
| 整体转化率 | L8/L1 | 1%-5% |

### 漏斗异常诊断

| 异常表现 | 可能原因 | 改进建议 |
|----------|----------|----------|
| 初筛通过率过低 | 职位要求过高/简历来源质量差 | 优化职位描述/拓宽渠道 |
| 电话沟通率低 | 沟通时间不当/话术问题 | 调整拨打时间/优化开场白 |
| Offer接受率低 | 薪资不具竞争力/候选人犹豫 | 优化薪酬方案/加强动机激发 |
| 入职率低 | 候选人反悔/CounterOffer | 做好入职跟进/提供过渡支持 |

## 渠道ROI分析

### 渠道ROI评估维度

| 维度 | 说明 |
|------|------|
| 候选人数量 | 各渠道获取的简历数量 |
| 候选人质量 | 各渠道候选人的匹配度评分 |
| 招聘周期 | 各渠道候选人的平均入职周期 |
| 招聘成本 | 各渠道的投入产出比 |
| 留存率 | 各渠道入职候选人的留存情况 |

### ROI计算公式

| 指标 | 计算公式 |
|------|----------|
| 渠道获取成本 | 渠道总花费 / 获取简历数 |
| 单个入职成本 | 渠道总花费 / 入职人数 |
| 渠道产出比 | 入职人数 / 渠道总花费 |
| 质量调整ROI | (入职人数 x 平均匹配度) / 渠道花费 |

| 渠道 | 简历数 | 入职数 | 总花费 | 入职成本 | 质量分 | ROI评分 |

| Boss直聘 | 500 | 15 | 5000 | 333 | 78 | 2.34 |
| 猎聘 | 200 | 12 | 8000 | 667 | 85 | 1.28 |
| 主流招聘平台 | 50 | 8 | 15000 | 1875 | 92 | 0.49 |
| LinkedIn | 100 | 5 | 3000 | 600 | 90 | 1.50 |
| 内部推荐 | 30 | 6 | 3000 | 500 | 88 | 1.76 |

## 预测性分析

### 留存概率预测模型

基于历史数据，预测候选人入职后的留存概率。

### 预测因素

| 因素类别 | 具体因素 | 影响方向 |
|----------|----------|----------|
| 候选人特征 | 工作经验年限 | 正向 |
| 候选人特征 | 学历水平 | 正向 |
| 候选人特征 | 薪资匹配度 | 正向 |
| 候选人特征 | 动机强度 | 正向 |
| 职位特征 | 职级匹配度 | 正向 |
| 职位特征 | 团队稳定性 | 正向 |
| 风险因素 | 通勤距离 | 负向 |
| 风险因素 | 家庭因素 | 负向 |
| 风险因素 | CounterOffer历史 | 负向 |

### 留存概率评分卡

| 评分区间 | 留存概率 | 风险等级 | 建议 |
|----------|----------|----------|------|
| 90-100分 | 95%+ | 极低 | 重点关注 |
| 80-89分 | 85%-95% | 低 | 正常跟进 |
| 70-79分 | 70%-85% | 中 | 加强沟通 |
| 60-69分 | 50%-70% | 高 | 重点跟进 |
| 60分以下 | <50% | 极高 | 谨慎推荐 |

## 数据可视化最佳实践

### 图表设计原则

| 原则 | 说明 |
|------|------|
| 简洁明了 | 避免过多装饰元素 |
| 数据准确 | 确保数据来源可靠 |
| 色彩一致 | 使用统一的配色方案 |
| 标注清晰 | 图表元素标注完整 |
| 断网可用 | 图表必须内嵌，不依赖CDN |

### 合规检查清单

- [ ] 所有图表使用SVG或base64图片，不依赖CDN
- [ ] 数据来源标注清晰
- [ ] 脱敏信息检查通过
- [ ] 日期为真实系统时间
- [ ] 响应式布局适配移动端
