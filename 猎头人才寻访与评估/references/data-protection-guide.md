## 一、PII四级分类标准

### 1.1 分类定义

| 级别 | 类型 | 示例字段 | 处理规则 |
|------|------|----------|----------|
| L1 | 公开信息 | 公司名称、行业 | 原样展示 |
| L2 | 内部信息 | 岗位名称、工作年限 | 可展示但报告标注"内部" |
| L3 | 敏感PII | 姓名、手机号、邮箱 | 交付前必须脱敏（掩码/替换） |
| L4 | 核心PII | 身份证号、银行卡号 | 严禁出现在交付物中，输入时即拦截 |

### 1.2 各级别详细处理规范

#### L1 公开信息

**定义**：已公开或可公开的信息，不涉及个人隐私

**字段示例**：
- 公司名称
- 所属行业
- 公司规模
- 公司官网
- 公开产品信息

**处理规则**：
- 原样展示
- 无需脱敏
- 可直接引用

#### L2 内部信息

**定义**：企业内部信息，非敏感但需标注来源

**字段示例**：
- 岗位名称
- 工作年限
- 学历背景
- 技能证书
- 项目经验（脱敏后）

**处理规则**：
- 可展示
- 报告需标注"内部信息"
- 不得用于跨企业对比

#### L3 敏感PII

**定义**：可直接识别个人身份的敏感信息

**字段示例**：
- 姓名
- 手机号
- 邮箱地址
- 家庭住址
- 薪资信息

**处理规则**：
- 交付前必须脱敏
- 脱敏方式：掩码/替换
- 示例：
  - 姓名 → [候选人A]
  - 手机号 → 138****5678
  - 邮箱 → ****@***.com
  - 住址 → **市**区

#### L4 核心PII

**定义**：高敏感个人信息，泄露可能导致严重后果

**字段示例**：
- 身份证号
- 银行卡号
- 社保号
- 护照号
- 生物识别信息

**处理规则**：
- 严禁出现在交付物中
- 输入时即拦截
- 发现后立即提示用户删除

### 1.3 PII识别与拦截流程

```
用户上传文件
    ↓
自动扫描PII字段
    ↓
┌─────────────────────────────────────┐
│ 发现L4核心PII？                      │
│   是 → 立即拦截，提示用户删除        │
│   否 → 继续处理                      │
└─────────────────────────────────────┘
    ↓
标记L3敏感PII
    ↓
生成报告前自动脱敏
    ↓
交付前二次检查
    ↓
输出合规交付物
```

## 二、防泄漏机制（关键保障）

### 2.1 主动加密

**机制说明**：用户上传的文档内容在进入分析流程前，系统自动触发AES-256加密

**加密规范**：

| 项目 | 要求 |
|------|------|
| 加密算法 | AES-256 |
| 密钥存储 | 仅本地存储，不上传至云端 |
| 加密时机 | 文档进入分析流程前 |
| 解密时机 | 仅分析流程内部使用 |

**加密流程**：
```
用户上传文档
    ↓
自动触发AES-256加密
    ↓
密钥本地存储（不上传云端）
    ↓
加密后内容进入分析流程
    ↓
分析完成 → 销毁解密后的临时数据
```

### 2.2 动态脱敏

**机制说明**：解析敏感字段时，自动进行脱敏处理

**脱敏规则**：

| 字段类型 | 脱敏规则 | 示例 |
|----------|----------|------|
| 姓名 | 替换为占位符 | [用户姓名] |
| 身份证号 | 保留首尾，中间掩码 | 110********1234 |
| 手机号 | 保留首尾，中间掩码 | 138*******5678 |
| 邮箱 | 用户名掩码，域名保留 | *********@*** |
| 住址 | 仅保留市区 | **市**区 |
| 银行卡号 | 保留首尾，中间掩码 | 6222********1234 |
| 薪资信息 | 替换为占位符 | [薪资信息] |

**脱敏示例**：
```
原始数据：
  姓名：张三
  手机：13812345678
  邮箱：zhangsan@example.com
  住址：北京市朝阳区建国路88号

脱敏后：
  姓名：[用户姓名]
  手机：138*******5678
  邮箱：*********@***
  住址：**市**区
```

### 2.3 边界隔离

**机制说明**：在回答用户问题、生成各项建议时，所有输出内容仅包含「脱敏后数据」或「基于加密后的分析结论」

**隔离规则**：

| 禁止行为 | 说明 |
|----------|------|
| 泄露原始文档全文 | 不得输出原始文档内容 |
| 泄露具体隐私信息 | 不得输出未脱敏的个人信息 |
| 跨任务数据引用 | 不得引用其他任务的数据 |
| 原始数据缓存 | 不得在输出中保留原始数据 |

**允许行为**：

| 允许行为 | 说明 |
|----------|------|
| 输出脱敏后数据 | 仅输出已脱敏的数据 |
| 输出分析结论 | 基于加密数据的分析结论 |
| 输出统计结果 | 汇总统计，不涉及个人数据 |

### 2.4 审计留痕

**机制说明**：对敏感信息处理过程生成「操作审计日志」，确保数据流向可追溯

**审计日志内容**：

| 日志项 | 说明 |
|--------|------|
| 操作时间 | 精确到秒 |
| 操作类型 | 上传/加密/脱敏/分析/输出/销毁 |
| 数据类型 | 文件类型/字段类型 |
| 处理结果 | 成功/失败 |
| 操作人员 | 系统自动/用户手动 |

**日志示例**：
```
[2026-03-23 10:30:15] 操作：用户上传文件
  文件类型：PDF简历
  处理结果：成功

[2026-03-23 10:30:16] 操作：AES-256加密
  加密算法：AES-256
  处理结果：成功

[2026-03-23 10:30:17] 操作：PII扫描
  发现L3敏感字段：姓名、手机号、邮箱
  处理结果：已标记待脱敏

[2026-03-23 10:30:18] 操作：动态脱敏
  脱敏字段：3个
  处理结果：成功

[2026-03-23 10:30:25] 操作：生成报告
  报告类型：人才匹配报告
  处理结果：成功

[2026-03-23 10:30:30] 操作：销毁临时数据
  销毁内容：解密后的临时数据
  处理结果：成功
```

**日志访问权限**：
- 仅开发人员可查看
- 用户无法查看原始日志
- 日志保留期限：90天

### 2.5 数据安全与隐私保护总结

**保护机制**：

| 机制 | 说明 |
|------|------|
| 全程加密 | AES-256加密，密钥本地存储 |
| 自动脱敏 | 敏感信息自动脱敏处理 |
| 边界隔离 | 输出仅含脱敏数据或分析结论 |
| 审计留痕 | 全流程操作日志可追溯 |
| 自动销毁 | 任务完成后自动销毁临时数据 |

**合规保障**：

| 保障项 | 说明 |
|--------|------|
| 隐私合规 | 严格遵循隐私合规标准 |
| 数据隔离 | 不向第三方共享用户数据 |
| 生命周期安全 | 确保数据全生命周期安全 |
| 用户授权 | 数据使用需用户确认授权 |

## 三、训练数据隔离声明（已移至第四章）

### 2.1 数据使用原则

| 原则 | 说明 |
|------|------|
| 当次任务专用 | 用户上传数据仅用于当次任务处理 |
| 非训练语料 | 不作为模型训练语料 |
| 无数据留存 | 处理完成后自动销毁 |
| 无原始输出 | 交付物不包含原始个人数据 |

### 2.2 声明模板

```
【训练数据隔离声明】

本技能运行时的用户上传数据（简历/薪酬表等）仅用于当次任务处理，
不作为模型训练语料。

交付物中不包含原始个人数据，仅输出分析结论。

您的数据安全得到以下保障：
- 数据隔离：与其他用户数据完全隔离
- 用途限制：仅用于当次分析任务
- 自动销毁：任务完成后自动清理
```

## 三、数据退役策略

### 3.1 退役流程

| 阶段 | 操作 | 说明 |
|------|------|------|
| 任务完成 | 原始文件销毁 | 沙箱环境自动清理 |
| 交付物生成 | 独立文件 | 不保留原始数据引用 |
| 会话结束 | 缓存清理 | 清除所有临时数据 |

### 3.2 数据生命周期

```
用户上传 → 任务处理 → 报告生成 → 交付输出 → 自动销毁
   ↓           ↓           ↓           ↓           ↓
 临时存储    内存处理    独立文件    用户下载    沙箱清理
```

### 3.3 退役确认清单

- [ ] 原始文件已删除
- [ ] 临时缓存已清理
- [ ] 会话数据已销毁
- [ ] 交付物为独立文件
- [ ] 无外部数据引用

## 四、公平性检查（薪酬+简历场景专用）

### 4.1 薪酬对比报告公平性

| 检查项 | 要求 | 说明 |
|--------|------|------|
| 样本量标注 | 必须 | 标注数据来源样本量 |
| 数据来源 | 必须 | 标注数据来源渠道 |
| 小样本警告 | 必须 | 样本量<30时标注"小样本，仅供参考" |
| 置信区间 | 建议 | 提供置信区间范围 |

### 4.2 简历匹配评分公平性

**禁止因素**（不得用于赋分）：
- 性别
- 年龄
- 民族
- 宗教信仰
- 婚育状况
- 残疾状况

**允许因素**（能力相关）：
- 技能匹配度
- 工作经验
- 学历背景
- 项目成果
- 行业经验

### 4.3 推荐/排名可解释性

| 要求 | 说明 |
|------|------|
| 评估维度标注 | 必须列出评估维度及权重 |
| 评分依据 | 必须说明评分依据 |
| 排名逻辑 | 必须说明排名逻辑 |
| 局限性说明 | 必须说明评估局限性 |

### 4.4 公平性声明模板

```
【公平性声明】

本报告的评估基于以下维度：
- [维度1]（权重XX%）
- [维度2]（权重XX%）
- [维度3]（权重XX%）

评估不包含以下因素：
- 性别、年龄、民族等非能力因素

评估局限性：
- 基于提供的数据进行分析
- 可能存在信息不完整的情况
- 建议结合面试等其他方式综合评估
```

## 五、PIPL合规声明模板

### 5.1 标准声明

```
【个人信息保护合规声明】

本报告中涉及的个人数据已依据《个人信息保护法》进行脱敏处理。

原始数据仅用于当次分析任务，处理完成后自动销毁。

数据来源：用户上传（已确认数据使用授权）。

合规保障措施：
1. 数据最小化：仅收集分析必需的数据
2. 目的限制：仅用于当次分析任务
3. 存储限制：任务完成后自动销毁
4. 安全保障：采用加密传输和存储
5. 透明公开：明确告知数据处理方式
```

### 5.2 简短声明（用于报告页脚）

```
本报告依据《个人信息保护法》进行数据处理。原始数据仅用于当次分析，
完成后自动销毁。数据来源：用户上传（已授权）。
```

| 数据退役 | [ ] | 已确认数据销毁 |

| PIPL声明 | [ ] | 已添加合规声明 |

### 6.2 自动化检查脚本

```python
def check_data_protection_compliance(content):
    """检查数据保护合规性"""
    issues = []
    
    # 检查L4核心PII
    l4_patterns = [
        r'\d{17}[\dXx]',  # 身份证号
        r'\d{16,19}',     # 银行卡号
    ]
    for pattern in l4_patterns:
        if re.search(pattern, content):
            issues.append("发现L4核心PII，必须删除")
    
    # 检查L3敏感PII是否脱敏
    l3_patterns = [
        r'1[3-9]\d{9}',   # 手机号（未脱敏）
        r'[\w.-]+@[\w.-]+\.\w+',  # 邮箱（未脱敏）
    ]
    for pattern in l3_patterns:
        if re.search(pattern, content):
            issues.append("发现L3敏感PII未脱敏")
    
    # 检查PIPL声明
    if '个人信息保护法' not in content:
        issues.append("缺少PIPL合规声明")
    
    return issues
```
