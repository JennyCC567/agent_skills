## 一、核心方法论

### 1.1 金字塔原理（总分总结构）

```
┌─────────────────────────────────────────┐
│           顶层：核心结论                  │
│    （一句话总结，首行必现）               │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│           中层：分层拆解                  │
│  ┌─────────────┐  ┌─────────────┐       │
│  │ 工作成果    │  │ 过程数据    │       │
│  └─────────────┘  └─────────────┘       │
│  ┌─────────────┐  ┌─────────────┐       │
│  │ KISS复盘    │  │ 问题卡点    │       │
│  └─────────────┘  └─────────────┘       │
│  ┌─────────────┐                        │
│  │ 下期计划    │                        │
│  └─────────────┘                        │
└─────────────────────────────────────────┘
                    ↓
┌─────────────────────────────────────────┐
│           底层：总结展望                  │
│    （承上启下，展望下一阶段）             │
└─────────────────────────────────────────┘
```

### 1.2 KISS复盘框架

| 维度 | 含义 | 核心问题 |
|------|------|----------|
| **Keep** | 保持 | 哪些做得好，需要继续保持？ |
| **Improve** | 改进 | 哪些需要改进优化？ |
| **Stop** | 停止 | 哪些应该停止，避免浪费？ |
| **Start** | 启新 | 哪些应该开始尝试？ |

### 1.3 敏捷工作逻辑

| 周期 | 迭代单位 | 核心目标 |
|------|----------|----------|
| 日迭代 | 单日冲刺 | 即时止损、当日闭环 |
| 周迭代 | 周度冲刺 | 阶段目标达成 |
| 月迭代 | 月度冲刺 | 战略方向校准 |

## 二、金字塔结构规范

### 2.1 结构要求

| 层级 | 内容 | 要求 |
|------|------|------|
| 顶层 | 核心结论 | 一句话总结，首行必现 |
| 中层 | 分层拆解 | 工作成果、过程数据、KISS复盘、问题卡点、下期计划 |

## 三、日报体系（日迭代·轻量化）

### 3.1 核心定位

| 定位 | 说明 |
|------|------|
| 单日敏捷冲刺同步 | 当日任务完成情况 |
| 即时问题止损 | 发现并解决当日问题 |
| 当日工作闭环 | 日清日结，不积压 |

### 3.2 日报结构

```
一、今日核心结论（金字塔前置总结）
   - 核心工作完成情况
   - 核心卡点
   - 明日核心目标

二、今日敏捷工作落地（数据化+实景示例）
   - 当日冲刺任务完成情况
   - 寻访数据
   - 候选人进度
   - 客户同步动作

三、今日KISS极简复盘
   - Keep（保持）
   - Improve（改进）
   - Stop（止损）
   - Start（启新）

四、当前项目卡点与求助
   - 现有卡点
   - 是否需要协助

五、明日冲刺计划（3-5项优先级任务）
```

### 3.3 日报完整示例

```
【日报】2026年3月23日 | 云计算算力架构团队招聘项目

一、今日核心结论
今日圆满完成本周冲刺阶段性寻访任务，高效完成2家竞品团队Mapping与首轮候选人触达，
整体进度符合冲刺预期；当前核心卡点为客户团队战略资料缺失，影响资深候选人转化，
明日将补齐行业寻访覆盖并优化沟通体系，持续推进项目落地。

二、今日敏捷工作落地
本周冲刺周期（第1周）核心目标为「完成云计算算力架构团队Mapping & 首轮候选人触达」。
今日已完成既定冲刺子任务：

1. 完成阿里云、腾讯云2家核心竞品算力基础设施部门组织架构梳理，输出简易架构图谱，
   筛选核心目标岗位（算力架构师、集群运维负责人）精准候选人36人；

2. 对36名目标候选人完成一对一精准破冰，有效触达18人，达成深度岗位沟通6人；

3. 实时同步客户今日寻访进度，同步2条一线市场动态：
   - 当前行业算力岗薪酬上浮10%
   - 高端人才跳槽窗口期集中在季度末

4. 全面更新项目敏捷看板，今日所有任务已全部移入「已完成」栏，无滞留、无积压待办。

三、今日KISS极简复盘

Keep（保持）：
- 严格遵循敏捷单日任务拆解逻辑，聚焦核心竞品核心岗位，未无效广撒网，寻访精准度大幅提升
- 沟通前提前匹配候选人项目经历与客户岗位需求，针对性答疑，候选人沟通意愿高、抵触率低
- 坚持日清日结，实时更新可视化看板，进度全程透明可追溯

Improve（改进）：
- 面对候选人「异地派驻、加班节奏」的顾虑，无标准化应答话术，临场解答不够统一专业
- 对小众自研算力架构岗位的市场对标信息储备不足，无法快速回应候选人专业疑问
- 单日工作节奏前松后紧，上午寻访效率偏低，晚间集中补量

Stop（止损）：
- 停止筛选非核心业务部门、资历不符的泛候选人，杜绝无效寻访耗时
- 停止无准备式临时沟通，降低沟通低效率
- 停止当日工作滞后补录、看板集中更新的陋习，杜绝信息更新不及时

Start（启新）：
- 明日整理「异地办公、加班机制」标准化应答话术，统一对外口径
- 专项收集小众算力岗位行业资料、薪酬对标数据，补充专业储备
- 重新排布每日工作节奏，上午主攻寻访触达，下午深耕深度沟通与信息整理，均衡推进任务

四、当前项目卡点与求助

现有卡点：
部分资深候选人关注客户团队未来3年业务规划与技术迭代方向，现有资料无法完整支撑答疑。

协助需求：
无团队协助需求，已同步客户，等待客户补充团队战略资料，以便提升候选人转化成功率。

五、明日冲刺计划

1. 完成华为云算力团队Mapping，补齐三大核心竞品人才库
2. 对今日6名深度沟通候选人完成简历标准化梳理与初筛评估
3. 落地新话术试用，完成10名新增候选人精准触达
4. 同步客户获取团队业务规划资料，解决当前转化卡点
```

## 六、KISS复盘方法论

### 6.1 KISS框架详解

#### Keep（保持）

**核心问题**：哪些做得好，需要继续保持？

**示例**：
- 严格遵循敏捷单日任务拆解逻辑，聚焦核心竞品核心岗位
- 沟通前提前匹配候选人项目经历与客户岗位需求
- 坚持日清日结，实时更新可视化看板

#### Improve（改进）

**核心问题**：哪些需要改进优化？

**示例**：
- 面对候选人顾虑，无标准化应答话术
- 对小众岗位的市场对标信息储备不足
- 单日工作节奏前松后紧

#### Stop（止损）

**核心问题**：哪些应该停止，避免浪费？

**示例**：
- 停止筛选非核心业务部门、资历不符的泛候选人
- 停止无准备式临时沟通
- 停止当日工作滞后补录

#### Start（启新）

**核心问题**：哪些应该开始尝试？

**示例**：
- 整理标准化应答话术，统一对外口径
- 专项收集小众岗位行业资料、薪酬对标数据
- 重新排布每日工作节奏

### 6.2 KISS复盘检查清单

| 维度 | 检查项 |
|------|--------|
| Keep | 是否识别出可复制的成功经验？ |
| Improve | 是否识别出需要改进的具体问题？ |
| Stop | 是否识别出应该停止的低效行为？ |
| Start | 是否识别出应该开始的新行动？ |

## 七、敏捷工作进度追踪

### 7.1 敏捷看板设计

```
┌─────────────┐  ┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│   待办      │  │   进行中    │  │   待确认    │  │   已完成    │
│  Backlog    │  │   Doing     │  │   Review    │  │    Done     │
├─────────────┤  ├─────────────┤  ├─────────────┤  ├─────────────┤
│ 任务1       │  │ 任务3       │  │ 任务5       │  │ 任务7       │
│ 任务2       │  │ 任务4       │  │ 任务6       │  │ 任务8       │
│             │  │             │  │             │  │             │
└─────────────┘  └─────────────┘  └─────────────┘  └─────────────┘
```

### 7.2 冲刺周期管理

| 周期 | 时长 | 核心动作 |
|------|------|----------|
| 日冲刺 | 1天 | 任务拆解、执行、复盘 |
| 周冲刺 | 1周 | 阶段目标、里程碑、复盘 |
| 月冲刺 | 1月 | 战略目标、趋势洞察、规划 |

### 7.3 进度可视化

| 指标 | 计算方式 | 目标值 |
|------|----------|--------|
| 任务完成率 | 已完成/总任务 | >=90% |
| 日清日结率 | 当日完成/当日计划 | =100% |
| 里程碑达成率 | 已达成/计划里程碑 | >=85% |

## 十、注意事项

1. **金字塔结构**：所有报告必须遵循总分总结构，核心结论前置
2. **数据化呈现**：工作成果必须有数据支撑，避免空泛描述
3. **KISS复盘**：每个维度必须有具体内容，不能空泛
4. **敏捷逻辑**：遵循冲刺周期管理，日清日结
5. **问题闭环**：卡点必须有解决方案或求助说明
6. **计划具体**：下期计划必须具体可执行，不能空泛
