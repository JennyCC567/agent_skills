## 核心原则：合规红线

在构建任何"关联"技能前，必须明确三条红线：

### 红线一：反爬虫条款

**法律依据**：几乎所有主流招聘平台（如Boss直聘、猎聘、LinkedIn等）的服务条款均明确禁止使用自动化脚本、机器人或第三方插件抓取非公开数据。

**违规行为**：
```
[否] 使用爬虫批量下载简历
[否] 使用自动化脚本模拟用户操作
[否] 使用机器人批量获取联系方式
[否] 使用第三方插件抓取非公开数据
[否] 绕过平台反爬机制
```

**法律后果**：
```
民事责任：
- 平台服务条款违约
- 账号永久封禁
- 损害赔偿

行政责任：
- 《网络安全法》处罚
- 《数据安全法》处罚

刑事责任：
- 非法获取计算机信息系统数据罪
- 侵犯公民个人信息罪
```

**真实案例警示**：
```
案例1：某猎头公司使用爬虫抓取Boss直聘数据
结果：账号被封禁，被平台起诉，赔偿50万元

案例2：某技术团队开发简历抓取工具并售卖
结果：构成侵犯公民个人信息罪，负责人被判刑

案例3：某公司批量存储候选人联系方式用于营销
结果：违反《个人信息保护法》，被罚款80万元
```

---

### 红线二：数据隐私

**法律依据**：候选人的联系方式、非公开简历属于个人隐私，未经授权不得聚合、存储或二次售卖。

**《个人信息保护法》核心要求**：
```
第一条：处理个人信息应当遵循合法、正当、必要原则
第二条：应当取得个人信息主体的同意
第三条：应当公开个人信息处理规则
第四条：应当采取必要的安全保护措施
```

**违规行为**：
```
[否] 未经授权聚合候选人联系方式
[否] 存储非公开简历到私有数据库
[否] 将候选人信息二次售卖给第三方
[否] 超出授权范围使用个人信息
[否] 拒绝候选人的删除请求
```

**法律责任**：
```
行政责任：
- 责令改正，给予警告
- 没收违法所得
- 罚款最高5000万元或上一年度营业额5%
- 责令暂停或终止提供服务
- 吊销相关业务许可

民事责任：
- 承担损害赔偿责任
- 公益诉讼

刑事责任：
- 侵犯公民个人信息罪
- 最高7年有期徒刑
```

**合规要点**：
```
[是] 获取候选人明确授权
[是] 仅存储必要信息
[是] 明确告知使用目的
[是] 提供删除和撤回授权渠道
[是] 定期清理过期数据
```

---

### 红线三：知识产权

**法律依据**：简历内容作为"汇编作品"，其版权归属于平台或用户本人，大规模复制即构成侵权。

**《著作权法》相关条款**：
```
第十四条：汇编若干作品、作品的片段或者不构成作品的数据或者其他材料，
对其内容的选择或者编排体现独创性的作品，为汇编作品，其著作权由汇编人享有。
```

**版权归属**：
```
平台用户协议通常规定：
- 简历的原始内容版权归用户本人所有
- 平台对简历的汇编、整理享有相关权利
- 用户授权平台使用、展示简历
- 第三方未经许可不得大规模复制
```

**违规行为**：
```
[否] 大规模复制简历内容
[否] 建立简历数据库用于商业目的
[否] 将简历内容用于培训AI模型
[否] 未经许可二次发布简历内容
[否] 剽窃简历中的项目描述用于其他用途
```

**法律后果**：
```
民事责任：
- 停止侵权
- 消除影响
- 赔礼道歉
- 赔偿损失

行政责任：
- 责令停止侵权
- 没收违法所得
- 罚款
```

**合规边界**：
```
[是] 单份简历的正常查看和使用
[是] 人工记录关键信息（非全文复制）
[是] 基于简历内容进行招聘决策
[是] 在授权范围内使用简历信息

[否] 批量复制简历全文
[否] 建立简历数据库对外服务
[否] 使用简历内容训练商业AI模型
[否] 将简历内容发布到其他平台
```

| 红线 | 核心禁止 | 合规边界 | 违规后果 |

| **知识产权** | 大规模复制简历内容 | 单份正常使用、人工记录 | 民事赔偿、行政处罚 |

## 数据安全与隐私保护

### 安全架构设计

#### 主动加密机制

**加密标准**：AES-256（高级加密标准）

**实现要点**：
```
1. 用户上传文档时自动触发加密
2. 密钥仅本地存储，不上传至云端
3. 加密后的数据才进入分析流程
4. 解密仅在授权的安全环境中进行
```

**密钥管理原则**：
```
- 密钥分离：分析与存储使用不同密钥
- 本地存储：密钥不离开用户设备
- 定期轮换：建议90天更换一次密钥
- 备份安全：密钥备份需加密并分散存储
```

---

#### 动态脱敏机制

**脱敏字段清单**：

| 字段类型 | 原始格式 | 脱敏后格式 | 脱敏规则 |
|---------|----------|------------|----------|
| 姓名 | 张三 | [用户姓名] | 替换为通用标识 |
| 身份证号 | 110101199001011234 | 110********1234 | 前6后4位保留 |
| 手机号 | 13812345678 | 138****5678 | 前3后4位保留 |
| 邮箱 | zhangsan@example.com | ****@*** | 域名和用户名均脱敏 |
| 住址 | 北京市朝阳区xxx街道 | **市**区 | 仅保留省市 |
| 银行卡号 | 622202xxxxxxxxx1234 | 6222***********1234 | 仅保留前4后4位 |
| 工资收入 | 25000元/月 | [薪资信息] | 替换为通用标识 |

**脱敏时机**：
```
1. 文档上传时：自动识别敏感字段
2. 内容解析时：敏感信息实时脱敏
3. 分析输出时：确保输出不含原始敏感信息
4. 报告生成时：仅使用脱敏后数据
```

---

#### 边界隔离机制

**输出内容限制**：

```
[是] 合规输出：
- 脱敏后的结构化数据
- 基于加密数据的分析结论
- 技能匹配度评分（不含原始简历）
- 推荐建议（基于脱敏信息）

[否] 禁止输出：
- 原始简历全文或大部分内容
- 具体隐私信息（如完整姓名、手机号）
- 未脱敏的个人身份信息
- 可追溯到原始文档的内容
```

**边界检查流程**：
```
1. 内容生成前：检查是否包含原始敏感信息
2. 输出过滤：敏感信息自动替换为[脱敏标识]
3. 人工抽检：定期抽检输出内容是否符合要求
4. 用户反馈：收集用户对隐私保护的反馈
```

---

### 审计留痕机制

#### 操作审计日志

**日志记录内容**：
```
1. 操作类型：上传、解析、分析、输出、删除
2. 操作时间：精确到秒的时间戳
3. 数据类型：处理的敏感信息类型
4. 操作结果：成功/失败
5. 操作人员：操作者身份标识
6. 关联业务：对应的招聘项目
```

**日志格式示例**：
```json
{
  "timestamp": "[填入真实系统时间]",
  "operation": "UPLOAD",
  "data_type": "RESUME",
  "sensitive_fields": ["NAME", "PHONE", "EMAIL"],
  "result": "SUCCESS",
  "user_id": "user_xxx",
  "project_id": "project_xxx"
}
```

**访问权限控制**：
```
查看权限：仅开发人员和安全管理员
存储期限：建议保留6个月以上
访问记录：所有查看操作均需记录
定期审计：每月审查日志完整性
```

## 概览
合规是AI辅助人才搜寻的底线，任何技术应用都必须在法律和平台规则框架内进行。

**核心原则**：
- 平台内操作为主，外部信息为辅
- 人工执行关键动作，AI仅辅助决策
- 不存储未经授权的个人信息
- 不进行自动化抓取

**法律责任**：
- 违反平台规则：账号封禁、法律责任
- 违反个人信息保护法：行政处罚、刑事责任
- 违反商业秘密：民事赔偿、刑事责任

市面上存在一些经过平台官方审核或基于浏览器自动化的插件，但需严格筛选。

#### 功能边界

**[是] 允许的功能**：
```
- 在单个平台页面上进行批量导出（平台自带功能）
```

### 路线三：X-ray人才地图（最安全且高阶）

这是最安全、且高阶的搜寻技能，利用搜索引擎的语法关联全网公开信息。

**技能点**：布尔检索语言（Boolean Search）+ X-ray。

#### 操作逻辑

**不直接入侵平台数据库**，而是利用Google/Bing的搜索指令，检索各大招聘平台的公开页面。

#### 布尔检索语法详解

**基础运算符**：
```
AND：包含所有关键词
示例：Java AND Spring AND MySQL

OR：包含任一关键词
示例：(架构师 OR 技术专家 OR 技术负责人)

NOT：排除关键词
示例：Java NOT JavaScript

""：精确匹配
示例："高级Java开发工程师"

()：分组组合
示例：(Java OR Python) AND (北京 OR 上海)
```

**X-ray搜索指令**：
```
site:限制搜索范围到指定网站
示例：site:zhaopin.com "Java架构师" AND "广州"

intitle:标题包含关键词
示例：intitle:"技术总监" site:linkedin.com

inurl:URL包含关键词
示例：inurl:resume Java developer

filetype:指定文件类型
示例：filetype:pdf "简历" Java
```

#### 关联逻辑

**通过公开信息构建候选人画像**：
```
LinkedIn公开档案 -> 职业轨迹、公司背景
GitHub -> 技术能力、项目经验
知乎 -> 专业见解、行业认知
微信公众号/博客 -> 行业动态、个人品牌
```

**优势**：
- 完全基于公开信息，不涉及违法
- 形成全方位的候选人画像
- 不依赖单一平台数据
- 可进行深度背景调研

#### 实战示例

**示例1：寻找Java架构师**
```
搜索语法：
site:linkedin.com "Java架构师" AND "北京" AND "分布式"

关联搜索：
site:github.com [候选人姓名]
site:zhihu.com [候选人姓名]
```

**示例2：目标公司人才挖掘**
```
搜索语法：
site:linkedin.com "阿里巴巴" AND "技术专家" AND "Java"

扩展搜索：
"阿里巴巴技术专家" site:github.com
"阿里巴巴架构师" site:zhihu.com
```

#### 注意事项

**合规边界**：
```
[是] 搜索公开页面（无需登录）
[是] 记录职业背景信息
[是] 了解技术能力
[否] 抓取需要登录的内容
[否] 批量自动化搜索
[否] 存储大量个人隐私
```

## 平台合规要求

### 主流招聘平台平台规则

#### [是] 允许的操作

**1. 正常使用平台功能**
```
- 使用平台搜索功能
- 查看简历详情
- 使用平台内置的高级筛选
- 平台内完成推荐动作
- 下载已授权的简历
```

**2. AI辅助分析**
```
- 人工复制简历文本到AI工具
- 使用AI分析已打开的简历
- 使用AI生成搜索关键词建议
- 使用AI生成匹配评分
```

**3. 内部决策参考**
```
- 使用AI生成的匹配报告
- 内部分享AI分析结果（非候选人联系方式）
- 基于AI建议执行人工操作
```

#### [否] 禁止的操作

**1. 自动化抓取**
```
[否] 使用爬虫批量下载简历
[否] 模拟点击自动执行操作
[否] 自动化脚本批量获取联系方式
[否] 绕过平台限制的技术手段
```

**违规后果**：
- 账号永久封禁

## 附件信息脱敏处理规范

### 基本原则

- 上传前必须完成脱敏处理
- 保护企业/个人数据安全
- 利用AI技术提升效率的同时确保数据安全

### 脱敏处理流程

```
上传前 -> 识别敏感字段 -> 脱敏处理 -> 上传AI系统 -> 分析结果 -> 输出验证
```

### 必须脱敏的字段

| 字段类型 | 示例 | 脱敏要求 |
|---------|------|----------|
| 个人姓名 | 张三 | 替换为[姓名]或[候选人A] |
| 身份证号 | 110101199001011234 | 110********1234 |
| 手机号 | 13812345678 | 138****5678 |
| 邮箱 | zhangsan@company.com | ****@*** |
| 住址 | 北京市朝阳区xxx | **市**区 |
| 银行卡号 | 622202xxxxxxxxx1234 | 仅保留前后各4位 |
| 工资收入 | 25000元/月 | [薪资信息] |

| 项目名称 | XX核心系统 | [项目名称] |

### 数据清洗步骤

**Step 1: 预上传检查**
- 识别文档中的敏感字段
- 确认是否包含商业机密
- 评估信息敏感程度

**Step 2: 脱敏处理**
- 替换个人身份信息
- 模糊化公司标识
- 隐藏财务/薪酬数据
- 删除可定位信息

**Step 3: 上传AI系统**
- 仅上传已脱敏内容
- 不上传原始文档
- 确保传输加密

**Step 4: 输出验证**
- 检查AI输出不含原始敏感信息
- 确认脱敏信息未泄露
- 验证报告安全性

## 第六部分：报告交付技术安全标准

### 一、核心原则

所有技能生成的报告（HTML/Word/PPT/Excel/PDF）必须遵守以下技术安全标准，确保文档在各种环境下均能正常查看和使用。

### 二、HTML图表安全规范

| 要求 | 说明 |
|------|------|
| **CDN禁止** | 严禁使用任何CDN链接加载图表库 |
| **库内嵌** | ECharts、Chart.js、D3.js等图表库必须内嵌完整代码 |
| **字体内嵌** | 自定义字体必须转为base64或使用系统字体 |

**正确做法**：
```html
<!-- 错误：使用CDN -->
<script src="https://cdn.echarts.com/echarts.js"></script>

<!-- 正确：内嵌完整库 -->
<script src="./lib/echarts.min.js"></script>
```

### 三、图片安全规范

| 要求 | 说明 |
|------|------|
| **base64内嵌** | 所有图片必须转换为base64格式内嵌 |
| **禁止外部URL** | 不引用任何外部图片链接 |
| **图标内嵌** | 图标必须内嵌，不使用外部字体图标库 |

**正确做法**：
```html
<!-- 错误：外部图片 -->
<img src="https://example.com/logo.png">

<!-- 正确：base64内嵌 -->
<img src="data:image/png;base64,iVBORw0KGgoAAAANS...">
```

### 四、Office文档图片规范

| 文档类型 | 要求 |
|----------|------|
| **PDF** | 图片完整嵌入，不依赖外部链接 |
| **Word** | 图片完整嵌入，不依赖外部链接 |
| **PPT** | 图片完整嵌入，不依赖外部链接 |
| **Excel** | 图片完整嵌入，不依赖外部链接 |

### 五、交付前验证清单

每次生成报告后，必须完成以下验证步骤：

| 验证阶段 | 验证内容 | 通过标准 |
|----------|----------|----------|
| **1. 在线正常** | 网络连接状态下文档可正常打开 | 图表渲染正常，图片显示正常 |
| **2. 断网正常** | 断开网络后文档仍可正常查看 | 无外部资源请求，所有内容可离线查看 |
| **3. 下载导出正常** | 各格式文档下载/导出功能 | PDF/Word/PPT/Excel均可正常下载 |
| **4. 多浏览器兼容** | 主流浏览器测试 | Chrome/Firefox/Safari/Edge均正常 |

**验证操作示例**：

## 一、PII四级分类标准

### 1.1 分类定义

| 级别 | 类型 | 示例字段 | 处理规则 |
|------|------|----------|----------|
| L1 | 公开信息 | 公司名称、行业 | 原样展示 |
| L2 | 内部信息 | 岗位名称、工作年限 | 可展示但报告标注"内部" |
| L3 | 敏感PII | 姓名、手机号、邮箱 | 交付前必须脱敏（掩码/替换） |
| L4 | 核心PII | 身份证号、银行卡号 | 严禁出现在交付物中，输入时即拦截 |

### 1.2 各级别详细处理规范

#### L1 公开信息

**定义**：已公开或可公开的信息，不涉及个人隐私

**字段示例**：
- 公司名称
- 所属行业
- 公司规模
- 公司官网
- 公开产品信息

**处理规则**：
- 原样展示
- 无需脱敏
- 可直接引用

#### L2 内部信息

**定义**：企业内部信息，非敏感但需标注来源

**字段示例**：
- 岗位名称
- 工作年限
- 学历背景
- 技能证书
- 项目经验（脱敏后）

**处理规则**：
- 可展示
- 报告需标注"内部信息"
- 不得用于跨企业对比

#### L3 敏感PII

**定义**：可直接识别个人身份的敏感信息

**字段示例**：
- 姓名
- 手机号
- 邮箱地址
- 家庭住址
- 薪资信息

**处理规则**：
- 交付前必须脱敏
- 脱敏方式：掩码/替换
- 示例：
  - 姓名 → [候选人A]
  - 手机号 → 138****5678
  - 邮箱 → ****@***.com
  - 住址 → **市**区

#### L4 核心PII

**定义**：高敏感个人信息，泄露可能导致严重后果

**字段示例**：
- 身份证号
- 银行卡号
- 社保号
- 护照号
- 生物识别信息

**处理规则**：
- 严禁出现在交付物中
- 输入时即拦截
- 发现后立即提示用户删除

### 1.3 PII识别与拦截流程

```
用户上传文件
    ↓
自动扫描PII字段
    ↓
┌─────────────────────────────────────┐
│ 发现L4核心PII？                      │
│   是 → 立即拦截，提示用户删除        │
│   否 → 继续处理                      │
└─────────────────────────────────────┘
    ↓
标记L3敏感PII
    ↓
生成报告前自动脱敏
    ↓
交付前二次检查
    ↓
输出合规交付物
```

## 二、防泄漏机制（关键保障）

### 2.1 主动加密

**机制说明**：用户上传的文档内容在进入分析流程前，系统自动触发AES-256加密

**加密规范**：

| 项目 | 要求 |
|------|------|
| 加密算法 | AES-256 |
| 密钥存储 | 仅本地存储，不上传至云端 |
| 加密时机 | 文档进入分析流程前 |
| 解密时机 | 仅分析流程内部使用 |

**加密流程**：
```
用户上传文档
    ↓
自动触发AES-256加密
    ↓
密钥本地存储（不上传云端）
    ↓
加密后内容进入分析流程
    ↓
分析完成 → 销毁解密后的临时数据
```

### 2.2 动态脱敏

**机制说明**：解析敏感字段时，自动进行脱敏处理

**脱敏规则**：

| 字段类型 | 脱敏规则 | 示例 |
|----------|----------|------|
| 姓名 | 替换为占位符 | [用户姓名] |
| 身份证号 | 保留首尾，中间掩码 | 110********1234 |
| 手机号 | 保留首尾，中间掩码 | 138*******5678 |
| 邮箱 | 用户名掩码，域名保留 | *********@*** |
| 住址 | 仅保留市区 | **市**区 |
| 银行卡号 | 保留首尾，中间掩码 | 6222********1234 |
| 薪资信息 | 替换为占位符 | [薪资信息] |

**脱敏示例**：
```
原始数据：
  姓名：张三
  手机：13812345678
  邮箱：zhangsan@example.com
  住址：北京市朝阳区建国路88号

脱敏后：
  姓名：[用户姓名]
  手机：138*******5678
  邮箱：*********@***
  住址：**市**区
```

### 2.3 边界隔离

**机制说明**：在回答用户问题、生成各项建议时，所有输出内容仅包含「脱敏后数据」或「基于加密后的分析结论」

**隔离规则**：

| 禁止行为 | 说明 |
|----------|------|
| 泄露原始文档全文 | 不得输出原始文档内容 |
| 泄露具体隐私信息 | 不得输出未脱敏的个人信息 |
| 跨任务数据引用 | 不得引用其他任务的数据 |
| 原始数据缓存 | 不得在输出中保留原始数据 |

**允许行为**：

| 允许行为 | 说明 |
|----------|------|
| 输出脱敏后数据 | 仅输出已脱敏的数据 |
| 输出分析结论 | 基于加密数据的分析结论 |
| 输出统计结果 | 汇总统计，不涉及个人数据 |

### 2.4 审计留痕

**机制说明**：对敏感信息处理过程生成「操作审计日志」，确保数据流向可追溯

**审计日志内容**：

| 日志项 | 说明 |
|--------|------|
| 操作时间 | 精确到秒 |
| 操作类型 | 上传/加密/脱敏/分析/输出/销毁 |
| 数据类型 | 文件类型/字段类型 |
| 处理结果 | 成功/失败 |
| 操作人员 | 系统自动/用户手动 |

**日志示例**：
```
[2026-03-23 10:30:15] 操作：用户上传文件
  文件类型：PDF简历
  处理结果：成功

[2026-03-23 10:30:16] 操作：AES-256加密
  加密算法：AES-256
  处理结果：成功

[2026-03-23 10:30:17] 操作：PII扫描
  发现L3敏感字段：姓名、手机号、邮箱
  处理结果：已标记待脱敏

[2026-03-23 10:30:18] 操作：动态脱敏
  脱敏字段：3个
  处理结果：成功

[2026-03-23 10:30:25] 操作：生成报告
  报告类型：人才匹配报告
  处理结果：成功

[2026-03-23 10:30:30] 操作：销毁临时数据
  销毁内容：解密后的临时数据
  处理结果：成功
```

**日志访问权限**：
- 仅开发人员可查看
- 用户无法查看原始日志
- 日志保留期限：90天

### 2.5 数据安全与隐私保护总结

**保护机制**：

| 机制 | 说明 |
|------|------|
| 全程加密 | AES-256加密，密钥本地存储 |
| 自动脱敏 | 敏感信息自动脱敏处理 |
| 边界隔离 | 输出仅含脱敏数据或分析结论 |
| 审计留痕 | 全流程操作日志可追溯 |
| 自动销毁 | 任务完成后自动销毁临时数据 |

**合规保障**：

| 保障项 | 说明 |
|--------|------|
| 隐私合规 | 严格遵循隐私合规标准 |
| 数据隔离 | 不向第三方共享用户数据 |
| 生命周期安全 | 确保数据全生命周期安全 |
| 用户授权 | 数据使用需用户确认授权 |

### 6.2 自动化检查脚本

```python
def check_data_protection_compliance(content):
    """检查数据保护合规性"""
    issues = []
    
    # 检查L4核心PII
    l4_patterns = [
        r'\d{17}[\dXx]',  # 身份证号
        r'\d{16,19}',     # 银行卡号
    ]
    for pattern in l4_patterns:
        if re.search(pattern, content):
            issues.append("发现L4核心PII，必须删除")
    
    # 检查L3敏感PII是否脱敏
    l3_patterns = [
        r'1[3-9]\d{9}',   # 手机号（未脱敏）
        r'[\w.-]+@[\w.-]+\.\w+',  # 邮箱（未脱敏）
    ]
    for pattern in l3_patterns:
        if re.search(pattern, content):
            issues.append("发现L3敏感PII未脱敏")
    
    # 检查PIPL声明
    if '个人信息保护法' not in content:
        issues.append("缺少PIPL合规声明")
    
    return issues
```
