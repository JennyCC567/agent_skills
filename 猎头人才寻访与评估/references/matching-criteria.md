## 概览
匹配评分是候选人筛选的核心环节，通过多维度评估候选人是否符合JD要求。

**适用范围**：所有职位类型的候选人匹配

**输出目标**：生成量化的匹配度评分（0-100分）

**效率提升**：
- 原人工筛选：2.4分钟/份
- AI辅助后：0.7分钟/份
- 人力减少：70%

**匹配精度目标**：
- 准确率：>=85%
- 召回率：>=80%
- F1分数：>=82%

## 评分维度

### 1. 硬性指标（权重：60%）

#### 1.1 学历匹配（权重：10%）
| JD要求 | 候选人学历 | 评分 |
|--------|-----------|------|
| 本科及以上 | 硕士 | 100分 |
| 本科及以上 | 本科 | 100分 |
| 本科及以上 | 大专 | 60分 |
| 本科及以上 | 高中及以下 | 20分 |
| 硕士及以上 | 硕士 | 100分 |
| 硕士及以上 | 本科 | 40分 |

**评分规则**：
- 完全符合或超出要求：100分
- 低一个层级：60-80分
- 低两个及以上层级：20-40分

#### 1.2 经验匹配（权重：20%）
| JD要求 | 候选人经验 | 评分 |
|--------|-----------|------|
| 3-5年 | 5年 | 100分 |
| 3-5年 | 4年 | 100分 |
| 3-5年 | 3年 | 100分 |
| 3-5年 | 2年 | 70分 |
| 3-5年 | 6年 | 90分 |
| 3-5年 | 1年 | 40分 |

**评分规则**：
- 完全符合要求范围：100分
- 经验略多（+1-2年）：90分
- 经验略少（-1年）：70分
- 经验差距较大：<50分

#### 1.3 技能匹配（权重：30%）
| JD要求 | 候选人技能 | 评分 |
|--------|-----------|------|
| Java、Spring、MySQL | Java、Spring、MySQL、Redis | 100分 |
| Java、Spring、MySQL | Java、Spring、MySQL | 100分 |
| Java、Spring、MySQL | Java、Spring | 70分 |
| Java、Spring、MySQL | Java | 40分 |

**评分规则**：
- 核心技能全部匹配：100分
- 核心技能匹配80%以上：80-90分
- 核心技能匹配50-80%：50-70分
- 核心技能匹配<50%：<50分

**特殊处理**：
- 对于"熟悉"、"精通"等程度词：
  - 精通 > 熟悉 > 了解
  - 候选人技能程度应与JD要求匹配

### 2. 软性指标（权重：30%）

#### 2.1 行业背景（权重：10%）
| 匹配程度 | 评分 |
|---------|------|
| 完全相同行业 | 100分 |
| 相关行业 | 70分 |
| 不同行业但有可迁移经验 | 40分 |
| 完全不同行业 | 20分 |

#### 2.2 软性能力（权重：10%）
| 能力类型 | 评估依据 | 评分 |
|---------|---------|------|
| 沟通能力 | 项目经历、面试反馈 | 1-100分 |
| 团队协作 | 项目角色、团队规模 | 1-100分 |
| 学习能力 | 技术栈广度、自我提升 | 1-100分 |
| 抗压能力 | 项目复杂度、加班经历 | 1-100分 |

**评估方法**：
- 从项目经历中推断
- 从面试反馈中获取
- 从职业发展轨迹中判断

#### 2.3 稳定性（权重：10%）
| 工作经历特点 | 评分 |
|------------|------|
| 每份工作2年以上 | 100分 |
| 每份工作1-2年 | 70分 |
| 多份工作<1年 | 40分 |

### 3. 优先条件（权重：10%）

**加分项处理**：
- 每个优先条件匹配：+10分
- 最多加30分（上限）

**示例**：
```
JD优先条件：
- 大型互联网公司经验
- 熟悉分布式架构
- 有开源项目经验

候选人情况：
- 有大型互联网公司经验 [匹配] +10分
- 不熟悉分布式架构 [不匹配] +0分
- 有开源项目经验 [匹配] +10分

总加分：20分
```

## 权重分配

### 默认权重分配
| 维度 | 权重 | 说明 |
|------|------|------|
| 硬性指标 | 60% | 学历、经验、技能 |
| 软性指标 | 30% | 行业、能力、稳定性 |
| 优先条件 | 10% | 加分项 |

### 动态调整规则
根据JD特点动态调整权重：

**技术岗位**：
- 技能匹配权重提升至40%
- 软性指标权重降至20%

**管理岗位**：
- 软性指标权重提升至40%
- 技能匹配权重降至20%

**初级岗位**：
- 学历权重提升至20%
- 经验权重降至10%

**高级岗位**：
- 经验权重提升至30%
- 学历权重降至5%

## 评分规则

### 单项评分流程
```
1. 读取JD要求
2. 读取候选人信息
3. 对照评分标准表
4. 计算单项得分
5. 说明评分依据
```

```

【综合匹配度】：85分

【硬性指标得分】：52.5/60分

- 稳定性：75分（每份工作约2年）-> 7.5分

【关键优势】：

- 缺少Redis使用经验

```

## 匹配度计算

### 计算公式
```
综合匹配度 = 硬性指标得分 + 软性指标得分 + 优先条件得分

其中：
硬性指标得分 = ∑(单项得分 x 单项权重) x 硬性指标权重
软性指标得分 = ∑(单项得分 x 单项权重) x 软性指标权重
优先条件得分 = 加分项总和（上限30分）x 优先条件权重
```

### 计算示例
```
综合匹配度 = 硬性指标得分 + 软性指标得分 + 优先条件得分

硬性指标得分 = 学历匹配分 + 经验匹配分 + 技能匹配分
             = 100分 x 10% + 90分 x 20% + 85分 x 30%
             = 10 + 18 + 25.5
             = 53.5分（满分60分）

软性指标得分 = 行业背景分 + 软性能力分 + 稳定性分
             = 70分 x 10% + 80分 x 10% + 75分 x 10%
             = 7 + 8 + 7.5
             = 22.5分（满分30分）

优先条件得分 = 加分项总和 x 10%
             = 20分 x 10%
             = 2分

综合匹配度 = 53.5 + 22.5 + 2 = 78分
           = 78分（满分100分）
           = 推荐级别：高（>=75分）
```

**权重与得分计算说明**：
- 硬性指标（满分60）：学历10% + 经验20% + 技能30% = 60%
- 软性指标（满分30）：行业背景10% + 软性能力10% + 稳定性10% = 30%
- 优先条件（满分10）：加分项总和 x 10%

**注意**：实际计算中，建议使用更精确的权重分配，此处示例简化了计算过程。

## Prompt模板使用

### 标准匹配评分Prompt

完整的Prompt模板见 [assets/prompt-templates.md](../assets/prompt-templates.md) 的"简历评分Prompt模板"部分。

**模板1：标准匹配评分**
```markdown
你是一位猎头顾问。请根据以下职位要求和简历内容，进行匹配度评分。

【职位要求】
技能矩阵：{必备技能及权重，加分技能}
硬性条件：{学历、年限等}
软性素质：{期望软性素质}

【输出】
1. 硬性条件是否满足（是/否，若不满足请说明）
2. 必备技能匹配情况（逐项列出匹配程度）
3. 加分技能匹配情况
4. 综合评分（0-100）
5. 匹配理由简述（2-3句话）

4. 在AI工具中运行Prompt

### 匹配精度数据

#### 指标定义

| 指标 | 定义 | 计算公式 | 目标 |
|------|------|---------|------|
| 准确率(Precision) | AI推荐中真正匹配的比例 | TP / (TP + FP) | >=85% |
| 召回率(Recall) | 真正匹配中被AI推荐的比例 | TP / (TP + FN) | >=80% |
| F1分数 | 准确率和召回率的调和平均 | 2 x (P x R) / (P + R) | >=82% |

**说明**：
- TP (True Positive)：AI推荐且人工确认为匹配
- FP (False Positive)：AI推荐但人工确认为不匹配
- FN (False Negative)：人工确认匹配但AI未推荐

#### 验证方法

**方法1：标准答案对比**
1. 准备测试数据集（5个职位，每个职位50份简历）
2. 资深顾问标注每份简历是否匹配（标准答案）
3. AI对每份简历进行评分
4. 设定阈值（如>=80分视为推荐）
5. 计算准确率、召回率、F1分数

**方法2：实际效果跟踪**
1. 记录AI推荐结果
2. 人工验证每份推荐
3. 记录面试结果和录用结果
4. 基于面试结果验证AI推荐质量

#### 精度验证示例

**测试数据**：
```
职位：高级Java开发工程师
简历数量：50份
人工标注匹配：15份
AI推荐（>=80分）：18份
```

**验证结果**：
```
| 指标 | 结果 | 目标 | 状态 |
|------|------|------|------|
| AI推荐数量 | 18份 | - | - |
| TP（AI推荐且人工确认） | 13份 | - | - |
| FP（AI推荐但人工否认） | 5份 | - | - |
| FN（人工确认但AI未推荐） | 2份 | - | - |
| 准确率 | 72% | >=85% | 未达标 |
| 召回率 | 87% | >=80% | 达标 |
| F1分数 | 79% | >=82% | 未达标 |
```

**改进措施**：
- 调整推荐阈值（从80分提升至85分）
- 优化评分权重
- 增加二次审核环节

#### 精度优化路径

**阶段1：初始验证**
- 目标：准确率>=75%，召回率>=75%
- 重点：验证评分体系合理性

**阶段2：优化调整**
- 目标：匹配精度目标（设计值）：准确率>=85%，召回率>=80%
- 重点：调整权重、优化Prompt

**阶段3：稳定运行**
- 目标：准确率>=90%，召回率>=85%
- 重点：持续监控、定期优化

### 质量保证建议

**建议1：建立标准数据集**
- 收集典型职位的简历样本
- 由资深顾问标注匹配结果
