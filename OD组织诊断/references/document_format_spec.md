# 文档输出格式规范（商务极简风）

---

## ⚠️ 红线规则（强制执行·禁止违反）

### 一、HTML报告红线
| 规则 | 要求 |
|------|------|
| CDN禁止 | ECharts等图表库**禁止**使用外部CDN，必须内嵌到HTML中 |
| 图片要求 | 所有图片**必须**Base64内嵌，不引用外部URL |
| 离线可用 | 下载后断网状态下**必须**所有功能正常 |

### 二、Office文档红线
| 格式 | 要求 |
|------|------|
| PDF | 图片完整嵌入，不依赖外部链接 |
| Word | 图片完整嵌入，不依赖外部链接 |
| PPT | 图片完整嵌入，不依赖外部链接 |
| Excel | 图片完整嵌入，不依赖外部链接 |

### 三、编码稳定性红线
| 规则 | 要求 |
|------|------|
| 字体 | **禁止**硬编码字体名称，必须使用跨平台字体检测函数 |
| 乱码 | 所有格式文档**必须**无文件名乱码、无内容乱码 |
| 日期 | **禁止**预设日期，必须自动填充真实系统时间 |

### 四、交付验证标准
```
✅ 在线正常 → ✅ 断网正常 → ✅ 各种格式文档下载/导出正常 → ✅ 多浏览器兼容
```
1. **在线打开**：所有格式文档图片正常显示
2. **断网打开**：下载后断网状态下图片仍正常显示
3. **导出验证**：PDF导出排版正常、无缺失、无变形
4. **多浏览器**：Chrome/Firefox/Safari/Edge/360均稳定

---

## 一、默认输出策略

**核心原则**：若用户未对文档输出格式提出明确要求，**默认统一输出 PDF 版与 HTML 版**，支持在线预览及一键下载，确保交付便捷、格式稳定。

- **HTML格式**：支持在线查看、一键下载、打印导出PDF
- **PDF格式**：支持直接下载、打印，适合正式存档和分享

---

## 二、HTML格式输出要求

### 2.1 界面格式选项
- **严格限制**：仅保留 **HTML版（在线查看 + 下载）和PDF版（一键下载）** 两种格式入口
- **隐藏其他**：Word、PPT、Excel等格式选项在HTML界面中隐藏，不显示
- **按钮位置**：所有操作按钮（下载HTML、导出PDF）及免责申明统一移至文档末尾

### 2.2 界面效果要求
- **流畅性**：界面加载流畅，无卡顿
- **响应式**：适配桌面端和移动端
- **一致性**：按钮样式统一，hover效果平滑

### 2.3 离线可用性
- **CDN内嵌**：ECharts等第三方库必须本地化内嵌，禁止使用外部CDN
- **断网兼容**：下载HTML后，断网状态下所有功能正常可用
- **图片稳定**：所有图片（Logo、图表等）必须Base64内嵌或本地相对路径引用

### 2.4 多浏览器兼容
- **测试浏览器**：Chrome、Firefox、Safari、Edge、360等主流浏览器
- **渲染一致**：确保各浏览器中图表和排版一致显示

---

## 三、PDF格式规范（HTML一键导出）

**重要说明**：PDF作为HTML的附带品，HTML文件本身支持一键导出PDF功能，无需单独生成PDF。

### 3.1 一键导出方式
- **操作入口**：HTML页面底部「📄 导出PDF」按钮
- **导出引擎**：html2pdf.js（已内嵌，离线可用）
- **输出格式**：A4标准商务排版，保留原HTML样式

### 3.2 格式要求
| 参数 | 规格 |
|------|------|
| 纸张 | A4 纵向 |
| 页边距 | 上下 2.5 cm，左右 3.0 cm |
| 行距 | 1.5 倍 |
| 段落 | 首行缩进 2 字符 |

### 3.2 字体规范
| 类型 | 字体 | 说明 |
|------|------|------|
| 中文 | 微软雅黑 | 跨平台自动适配 |
| 英文/数字 | Times New Roman | 标准商务字体 |
| 颜色 | 全文黑色 | 仅重点可加粗 |

### 3.3 标题层级
| 层级 | 字号 | 加粗 | 对齐 | 示例 |
|------|------|------|------|------|
| 一级标题 | 小二/二号 | 是 | 居中 | 一、项目概述 |
| 二级标题 | 四号 | 是 | 左对齐 | 1.1 项目背景 |
| 三级标题 | 小四 | 是 | 左对齐 | 1.1.1 背景分析 |

**编号规范**：统一使用 `1 / 1.1 / 1.1.1` 三级编号体系

### 3.4 正文要求
| 参数 | 规格 |
|------|------|
| 字号 | 小四号（12pt） |
| 对齐 | 两端对齐 |
| 行距 | 1.5倍 |
| 空行 | 无多余空行 |
| 格式 | 无彩色、无特殊格式 |

### 3.5 图表表格规范
| 类型 | 要求 |
|------|------|
| 图片 | 清晰、居中、不变形 |
| 表格 | 边框完整、内容对齐统一 |
| 编号 | 图 1、表 1（按章节编号） |
| 图注/表注 | 小五号字体，居中显示 |

### 3.6 输出与命名
| 类型 | 生成方式 | 命名规范 |
|------|----------|----------|
| HTML | 脚本直接生成 | `文档名-版本-日期.html` |
| PDF | HTML一键导出 | `文档名-版本-日期.pdf` |

**示例**：`OD诊断报告-v1.0-20250115.html` / `OD诊断报告-v1.0-20250115.pdf`

## 四、下载稳定性要求

### 4.1 文件名稳定性
- **无乱码**：文件名使用中英文时，确保编码正确，不出现乱码
- **规范命名**：按照"文档名-版本-日期"格式命名

### 4.2 内容稳定性
- **无乱码**：所有格式文档内容中文正常显示，无编码异常
- **无丢失**：图表、图片、数据完整，无缺失
- **无错位**：排版整齐，图表位置正确

### 4.3 跨平台支持
- **Windows**：微软雅黑、宋体、黑体
- **macOS**：PingFang SC、STHeiti、STSong
- **Linux**：Noto Sans CJK SC、WenQuanYi Micro Hei

所有脚本必须实现跨平台中文字体自动检测和适配。

---

## 五、格式修复与验证标准

### 5.1 修复要求
彻底修复最终生成的 **HTML、PDF、Word、PPT、Excel** 等格式文档中部分图片无法正常显示的问题，修复后确保报告：
- **完整性**：所有内容完整，无缺失
- **稳定性**：各浏览器/平台渲染一致
- **无丢失**：图片、图表正常加载
- **无错位**：排版整齐，无异常
- **无变形**：图片比例正确，不拉伸

### 5.2 验证清单（必须全部通过方可交付）

#### 5.2.1 在线打开验证
- 在线打开 HTML、PDF、Word、PPT、Excel 等格式文档
- 所有图片（Logo、核心绩效图表、软技能雷达图、对比分析图）均正常显示

#### 5.2.2 离线打开验证
- 下载报告后，在**断网状态**下重新打开
- 所有图片仍正常显示
- ECharts等交互图表正常渲染

#### 5.2.3 PDF导出验证
- 通过浏览器打印或工具内置PDF导出的报告
- 所有图片排版正常、无缺失、无变形

#### 5.2.4 多浏览器兼容验证
- 报告在 **Chrome、Firefox、Safari、Edge、360** 等主流浏览器中均稳定显示
- 确保各浏览器中字体、图表、排版一致

### 5.3 技术验证要点
- **ECharts CDN内嵌**：`assets/echarts.min.js` 存在且可用
- **中文字体检测**：所有脚本实现 `get_chinese_font_name()` 函数
- **Base64图片**：HTML中的图片使用Base64内嵌或本地相对路径
- **跨平台测试**：Windows/macOS/Linux均验证通过
