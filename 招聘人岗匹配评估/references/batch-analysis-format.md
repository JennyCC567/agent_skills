## 批量处理性能优化指南

### 进度条可视化方案

在HTML报告中嵌入CSS进度条，实时展示批量处理进度：

```html
<div class="progress-container">
  <div class="progress-bar" style="width: 30%;">
    <span class="progress-text">已处理 3/10</span>
  </div>
</div>
<style>
.progress-container {
  width: 100%;
  background-color: #e0e0e0;
  border-radius: 8px;
  overflow: hidden;
  margin: 10px 0;
}
.progress-bar {
  height: 24px;
  background: linear-gradient(90deg, #4CAF50, #66BB6A);
  border-radius: 8px;
  transition: width 0.3s ease;
  display: flex;
  align-items: center;
  justify-content: center;
}
.progress-text {
  color: white;
  font-size: 12px;
  font-weight: bold;
}
</style>
```

进度条宽度按 `（已处理数 / 总数）× 100%` 动态计算，每完成一份简历即时更新。

### 分批输出策略

- 每完成 **5份简历** 输出一次中间结果，避免用户长时间等待无反馈
- 中间结果包含：已完成候选人的简要评分、匹配结论及关键发现
- 全部处理完成后输出完整汇总报告
- 若总数不足5份，则在每份完成后逐条输出

### 预估剩余时间算法

基于前N份简历的平均处理时间推算剩余时间：

```
预估剩余时间 = （总数 - 已处理数） × 前 N 份平均处理时间

其中：
- N = min(已处理数, 5)，取已处理数与5的较小值
- 前 N 份平均处理时间 = 前 N 份简历的总耗时 / N
- 首份简历完成前，使用默认预估值（8秒/份）
```

示例：已处理3份，耗时分别为6s、7s、8s，剩余7份：
- 平均耗时 = (6+7+8)/3 = 7s
- 预估剩余 = 7 × 7s = 49s

### 超时处理

- 单份简历处理超过 **30秒** 自动跳过并标记
- 标记格式：在候选人结果中标注 `⚠️ 处理超时（>30s），已跳过`
- 跳过的简历不计入评分统计，但保留在汇总列表中
- 超时原因常见：简历格式异常、内容过长、附件解析失败等

### 并发建议

| 简历数量 | 建议策略 | 每批数量 | 说明 |
|---------|---------|---------|------|
| 1-5份 | 顺序处理 | - | 数量少，无需分批 |
| 6-10份 | 分2批 | 5份/批 | 减少单次等待时间 |
| 10份以上 | 分批处理 | 5份/批 | 每批5份，批次间保留进度反馈 |

每批处理完成后输出进度信息，再继续下一批。
