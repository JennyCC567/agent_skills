# FABM 模型完整指南

## 概览

FABM 模型是猎头行业用于生成精准、有说服力推荐报告的核心方法论。通过四个维度的系统化呈现，高效连接人才与企业需求。

## 1. FABM 模型概述

FABM 模型四步法是生成高质量猎头推荐报告的标准流程：

| 维度 | 名称 | 核心目标 | 关键要点 |
|------|------|----------|----------|
| **F** | Features（基础信息） | 精准锚定人才标签 | 硬性条件、核心标签、隐藏价值 |
| **A** | Achievements（关键成就） | 用结果证明能力 | STAR 法则结构化呈现 |
| **B** | Benefits（客户价值） | 聚焦企业实际需求 | 精准对标、数据佐证、推荐伏笔 |
| **M** | Motivation（跳槽动机） | 构建合理跳槽逻辑 | 内在驱动、外在吸引 |

## 2. F - Features（基础信息）

### 2.1 硬性条件

精准呈现基础信息，锚定人才标签：

- **基本信息**：姓名、年龄、性别
- **教育背景**：学历、毕业院校、专业
- **工作经验**：工作年限、行业经验
- **当前状态**：现任职公司、当前职位

**格式示例**：
```
姓名：王某某
年龄：32岁
学历：本科（计算机科学与技术，清华大学）
工作年限：10年
当前公司：阿里巴巴
当前职位：高级技术专家
```

### 2.2 核心标签

提炼与客户需求直接对标的核心标签：

- **现任职公司 + 职位**：体现当前职业高度
- **核心技能标签**：匹配岗位要求的关键技能
- **行业经验标签**：相关行业背景

**格式示例**：
```
核心标签：
- 大型互联网公司核心架构经验
- 高并发系统设计与优化专家
- 双十一大促技术负责人
```

### 2.3 隐藏价值

挖掘附加资源，提升候选人竞争力：

- **行业人脉**：关键领域的专家资源
- **技术专利**：相关技术领域的专利成果
- **竞品经验**：对标公司或竞品项目经验
- **特殊资源**：稀缺的行业资源或经验

**格式示例**：
```
隐藏价值：
- 曾深度参与阿里双十一大促系统架构设计，积累的高并发流量应对经验可直接复用至贵司 618 流量洪峰预案
- 拥有分布式系统领域 3 项技术专利
- 具备拼多多、京东等电商平台技术团队人脉资源
```

## 3. A - Achievements（关键成就）

### 3.1 STAR 法则结构化呈现

采用 STAR 法则结构化呈现关键成就，用结果证明能力：

| 要素 | 含义 | 关键问题 | 示例 |
|------|------|----------|------|
| **S** | Situation（背景） | 业务规模？技术难点？ | 负责双十一大促核心交易系统，峰值 QPS 达 50 万 |
| **T** | Task（任务） | 核心职责？目标是什么？ | 确保系统稳定性，将故障率控制在 0.01% 以下 |
| **A** | Action（行动） | 创新方案？技术亮点？ | 引入全链路压测、智能限流降级、异地多活架构 |
| **R** | Result（结果） | 数据化成果？价值体现？ | 系统稳定运行，故障率为 0，支撑 GMV 突破 4982 亿 |

### 3.2 成就呈现示例

**示例 1：系统性能优化**
```
背景（S）：负责电商平台核心交易系统，日常 QPS 5k，大促期间 QPS 达 50k
任务（T）：优化系统性能，确保大促期间系统稳定性
行动（A）：
- 引入 Redis 缓存集群，优化热点数据访问
- 实施数据库分库分表，解决单库性能瓶颈
- 设计熔断降级机制，保护核心业务
结果（R）：将系统 QPS 从 5k 优化至 12k，同时降低服务器成本 40%
```

**示例 2：技术架构重构**
```
背景（S）：原有单体架构无法支撑业务快速增长，部署周期长达 2 周
任务（T）：重构为微服务架构，提升系统扩展性和部署效率
行动（A）：
- 设计微服务拆分方案，按业务域拆分为 15 个服务
- 引入 Spring Cloud 生态，实现服务注册发现、配置中心
- 搭建 CI/CD 流水线，实现自动化部署
结果（R）：部署周期缩短至 2 小时，系统可用性从 99.5% 提升至 99.99%
```

**示例 3：团队管理成果**
```
背景（S）：新组建的团队，成员经验不足，项目交付延期率高达 40%
任务（T）：提升团队能力和项目管理效率
行动（A）：
- 建立技术培训体系，每周组织技术分享
- 引入敏捷开发流程，实施两周一迭代
- 建立代码审查机制，提升代码质量
结果（R）：团队技术能力显著提升，项目交付延期率降至 5%，团队年度流失率为 0
```

### 3.3 成就挖掘要点

**从简历中挖掘关键成就**：
1. **关注数据**：寻找百分比、数量、时间等量化指标
2. **关注对比**：优化前后的对比数据
3. **关注结果**：业务价值、技术价值、团队价值
4. **关注创新**：技术创新、方案创新、流程创新

**提问引导候选人补充**：
- 这个项目的业务规模有多大？
- 你在这个项目中承担什么角色？
- 你是如何解决这个技术难点的？
- 最终取得了什么成果？有数据支撑吗？

## 5. M - Motivation（跳槽动机）

### 5.1 内在驱动

构建合理的跳槽逻辑，呈现个人发展需求：

**技术瓶颈突破**：
```
跳槽动机：
- 当前公司技术体系相对成熟，个人技术成长空间有限
- 希望在贵司的技术挑战中突破技术瓶颈
- 对贵司正在探索的云原生技术方向非常感兴趣
```

**业务成长空间**：
```
跳槽动机：
- 当前业务线已进入稳定期，缺乏新的业务挑战
- 希望在贵司快速发展的业务中承担更大责任
- 看重贵司在行业中的领先地位和成长空间
```

**职业发展规划**：
```
跳槽动机：
- 希望从纯技术专家向技术管理转型
- 贵司的技术管理岗位设置更符合个人职业规划
- 期待带领更大的团队，创造更大的业务价值
```

### 5.2 外在吸引

基于调研的企业亮点，呈现客户公司的独特优势：

**公司优势**：
```
对贵司的兴趣点：
- 贵司在行业中的领先地位和品牌影响力
- 正在进行的业务转型和技术升级
- 开放包容的技术文化和创新氛围
- 具有竞争力的薪酬体系和股权激励
```

**团队优势**：
```
对团队的关注点：
- 技术团队的规模和专业度
- 团队的技术氛围和学习文化
- 直接汇报对象的技术背景和管理风格
```

**项目优势**：
```
对项目的期待：
- 核心业务的技术挑战性
- 项目的业务价值和社会意义
- 技术栈的先进性和学习价值
```

### 5.3 跳槽动机呈现示例

**完整示例**：
```
跳槽动机分析：

内在驱动：
- 技术瓶颈：当前公司技术体系成熟，个人成长空间有限，希望在新技术领域突破
- 职业发展：期望从技术专家向技术管理转型，承担更大责任
- 业务挑战：希望参与更具挑战性的业务项目，创造更大的业务价值

外在吸引：
- 公司地位：贵司在行业中的领先地位和快速成长性
- 技术方向：正在探索的云原生、AI 等前沿技术方向
- 团队文化：开放包容的技术氛围和创新文化
- 薪酬待遇：具有竞争力的薪酬体系和股权激励

跳槽合理性：★★★★★
候选人跳槽动机明确，逻辑清晰，与客户需求高度匹配，跳槽可能性高。
```

## 6. 避坑指南

### 6.1 模糊表述 vs 量化呈现

| ❌ 错误示例 | ✅ 正确示例 |
|-----------|-----------|
| 熟悉 Python 编程语言 | 通过 Python 实现点击率预估模型，将 AUC 指标提升 15% |
| 具备较强的学习能力 | 曾在 3 个月内从 0 搭建 ELK 日志分析系统，为团队问题排查节省 50% 工时 |
| 熟悉分布式系统 | 设计并实施分布式缓存方案，支撑日均 1 亿请求，系统延迟降低 60% |

### 6.2 空泛评价 vs 实例证明

| ❌ 错误示例 | ✅ 正确示例 |
|-----------|-----------|
| 具备团队协作能力 | 作为技术负责人，协调 3 个团队完成跨部门项目，提前 1 周交付 |
| 有项目管理经验 | 主导 5 人团队完成 2 个大型项目，项目按期交付率 100% |
| 沟通能力强 | 作为技术顾问，成功推动业务方采纳技术方案，节约研发成本 30% |

### 6.3 无效描述 vs 数据佐证

| ❌ 错误示例 | ✅ 正确示例 |
|-----------|-----------|
| 显著提升了系统性能 | 将系统 QPS 从 5k 优化至 12k，同时降低服务器成本 40% |
| 改善了用户体验 | 优化页面加载速度，首屏时间从 3s 降至 1.2s，用户留存率提升 20% |
| 提高了团队效率 | 引入自动化测试框架，测试覆盖率从 40% 提升至 90%，测试时间缩短 60% |

### 6.4 推荐报告常见问题

**问题 1：信息过载**
- ❌ 罗列候选人所有项目经历
- ✅ 精选 2-3 个与岗位最匹配的核心成就

**问题 2：缺乏针对性**
- ❌ 一份报告投递所有客户
- ✅ 根据客户 JD 定制匹配分析

**问题 3：主观评价过多**
- ❌ "我认为候选人非常优秀"
- ✅ 用数据和事实说话，让客户自己判断

**问题 4：忽略风险提示**
- ❌ 只呈现优势，隐藏风险
- ✅ 客观呈现风险点，体现专业度

## 8. 使用说明

### 8.1 FABM 分析流程

1. **收集信息**：从简历、面试中提取候选人信息
2. **梳理 Features**：整理基础信息、核心标签、隐藏价值
3. **挖掘 Achievements**：用 STAR 法则提炼关键成就
4. **匹配 Benefits**：逐条对标岗位需求，分析客户价值
5. **分析 Motivation**：构建合理的跳槽逻辑
6. **生成报告**：整合四个维度，输出推荐报告

### 8.2 信息挖掘要点

**从简历中挖掘**：
- 教育背景 → Features
- 工作经历 → Features + Achievements
- 项目经验 → Achievements
- 技能证书 → Features + Benefits

**从面试中挖掘**：
- 项目细节 → Achievements
- 跳槽原因 → Motivation
- 薪资期望 → Benefits
- 职业规划 → Motivation

### 8.3 质量检查清单

- [ ] Features 是否完整且精准？
- [ ] Achievements 是否用 STAR 法则呈现？
- [ ] Achievements 是否包含量化数据？
- [ ] Benefits 是否精准对标岗位需求？
- [ ] Motivation 是否构建了合理的跳槽逻辑？
- [ ] 是否避免了模糊表述和空泛评价？
- [ ] 是否客观呈现了风险点？
